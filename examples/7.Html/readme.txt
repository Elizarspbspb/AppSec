Защита HTML — заблокировать возможность проведения атак XSS (кража кук) и CSRF (подделка запросов).

КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО в HTML:
1. Инлайн-скрипты (Inline Scripts):
Категорически запрещено писать JS-код прямо внутри тегов, например: <script>alert('test')</script>. Если хакер сможет провернуть XSS, его код выполнится мгновенно.
2. Инлайн-обработчики событий (Inline Event Handlers):
Запрещено использовать конструкции вроде <body onload="..."> или <button onclick="...">. Это главный вектор для внедрения вредоносных скриптов через уязвимые поля ввода.
3. Отсутствие валидации контекста ссылок:
Запрещено слепо вставлять пользовательские ссылки в тег <a href="...">. Хакер может подставить туда ссылку вида href="javascript:stealCookies()", и при клике выполнится его код.


ОБЯЗАТЕЛЬНО должно быть внедрено (Параметры безопасности):
1. Content Security Policy (CSP): Самый мощный заголовок (или мета-тег). Он говорит браузеру: «Загружай скрипты ТОЛЬКО с нашего сервера. Все инлайн-скрипты и чужие сайты — блокируй».
2. Атрибуты rel="noopener noreferrer": Обязательны для всех внешних ссылок, открывающихся в новом окне (target="_blank"), чтобы чужой сайт не мог получить контроль над вкладкой пользователя через уязвимость Reverse Tabnabbing.
3. Защитные атрибуты в формах: Использование autocomplete="off" для чувствительных данных (пароли, коды из СМС) и встроенная валидация типов.
4. required - это обычный встроенный атрибут HTML5 для проверки форм. Когда вы ставите <input type="text" required>, браузер пользователя сам проверяет, заполнено ли поле.
Хакер может легко зайти в отладчик браузера и удалить этот атрибут required из HTML-кода и отправить на сервер пустой запрос. 
Поэтому любая проверка на фронтенде должна обязательно дублироваться валидацией на бэкенде (сервере).
