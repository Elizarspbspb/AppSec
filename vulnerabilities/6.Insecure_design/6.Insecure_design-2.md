# Краткое руководство по Insecure Design

## Что такое Insecure Design
**Insecure Design** — уязвимости, возникающие из-за ошибок проектирования архитектуры и бизнес-логики приложения, а не из-за ошибок кода. Проблема закладывается на этапе проектирования.

## Основные типы уязвимостей
* **Неправильная модель доступа**
  * Пример: отсутствие проверки принадлежности данных пользователю
  * Атака: получение доступа к чужим данным через изменение ID

* **Обход бизнес-процессов**
  * Пример: API принимает статус оплаты без проверки
  ```json
  {
    "product": "Laptop",
    "payment_status": "success"
  }
  ```
  * Атака: прямая отправка успешного статуса оплаты

* **Доверие клиентским данным**
  * Пример: проверка роли пользователя на клиенте
  ```python
  if role == "admin":
      open_admin_panel()
  ```
  * Атака: подмена роли в запросе

* **Жёстко закодированные секреты**
  * Пример: хранение паролей в коде
  ```python
  DATABASE_PASSWORD = "admin123"
  ```

## Методы поиска уязвимостей
* Анализ ролей пользователей и их возможностей
* Проверка изменения критичных параметров
* Тестирование последовательности действий
* Поиск обходных путей в бизнес-логике
* Проверка обработки ошибок

## Способы защиты
* Внедрение **Threat Modeling** на этапе проектирования
* Применение принципов:
  * Защита по умолчанию
  * Минимальные привилегии
  * Отказ по умолчанию

* Правильная архитектура:
  * Хранение ролей на сервере
  * Проверка статусов через внутренние механизмы
  * Использование менеджеров секретов

* Внедрение защиты от автоматизированных атак:
  * Rate Limiting
  * CAPTCHA
  * Мониторинг активности

* Пример безопасного хранения секретов:
```python
# Вместо:
API_KEY = "secret-key"

# Использовать:
api_key = get_secret_from_vault("api-key")
```

## Ключевые моменты защиты
* Привлекать специалистов безопасности на этапе проектирования
* Документировать требования безопасности
* Проводить независимое тестирование архитектуры
* Внедрять безопасность на всех этапах разработки
