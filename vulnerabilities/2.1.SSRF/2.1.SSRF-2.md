# SSRF (Server-Side Request Forgery) — краткое руководство для AppSec специалиста

## Что такое SSRF
**SSRF** — уязвимость, позволяющая злоумышленнику заставить сервер выполнять запросы к произвольным ресурсам. Сервер может обращаться как к внутренним сервисам организации, так и к внешним системам.

## Основные последствия
* Доступ к внутренним системам
* Кража конфиденциальных данных
* Обход сетевых ограничений
* Выполнение команд на сервере
* Проведение атак от имени организации

## Типичные векторы атак
**Атака на локальный сервер:**
```http
POST /product/stock HTTP/1.0
Content-Type: application/x-www-form-urlencoded

stockApi=http://localhost/admin
```

**Атака на внутренние системы:**
```http
stockApi=http://192.168.0.68/admin
```

## Способы обхода защит
* Альтернативные представления IP (127.0.0.1 → 2130706433)
* Использование DNS-подмены
* URL-кодирование запрещённых строк
* Манипуляции с HTTP-редиректами
* Использование поддоменов

## Методы поиска уязвимостей
* Проверка параметров с URL
* Анализ XML-парсеров
* Тестирование заголовков Referer
* Поиск частичных URL в запросах
* Проверка механизмов загрузки файлов

## Защита от SSRF
**Основные меры:**
* Использование белого списка разрешённых доменов
* Проверка конечного IP после DNS-разрешения
* Отключение автоматического следования редиректам
* Ограничение исходящих соединений на уровне FW
* Защита внутренних сервисов аутентификацией
* Логирование всех исходящих запросов

**Пример безопасной реализации:**
```python
# Белый список разрешённых доменов
ALLOWED_DOMAINS = ['api.example.com', 'service.example.com']

def is_safe_url(url):
    parsed = urlparse(url)
    if parsed.hostname not in ALLOWED_DOMAINS:
        return False
    # Проверка на внутренние IP
    try:
        ip = socket.gethostbyname(parsed.hostname)
        if ip.startswith(('10.', '172.', '192.168.')):
            return False
    except:
        return False
    return True
```

## Ключевые моменты для проверки
* Все параметры с URL
* Интеграции с внешними API
* Механизмы загрузки файлов
* Обработка XML и других форматов
* HTTP-заголовки
* Webhooks и callback-URL

> Эффективная защита требует многоуровневого подхода: валидация входных данных + проверка конечного адреса + ограничение сетевых соединений.
