# Software Supply Chain Failures: Краткое руководство для AppSec специалиста

## Что такое уязвимости цепочки поставок
**Software supply chain failures** — класс уязвимостей, возникающих при нарушении безопасности на любом этапе жизненного цикла ПО: от разработки до доставки конечному пользователю.

## Основные типы атак
* **Компрометация зависимостей** — заражение через сторонние библиотеки (npm, pip, Maven)
* **Dependency Confusion** — подмена внутренних пакетов публичными
* **Атака на CI/CD** — компрометация процессов сборки
* **Зараженные контейнеры** — внедрение вредоносного кода в Docker-образы

## Способы поиска уязвимостей
**Анализ зависимостей:**
* npm audit для Node.js
* pip-audit для Python
* Maven dependency-check
* Сканирование HTTP-ответов на версии фреймворков

**Поиск Dependency Confusion:**
* Проверка package.json на внутренние названия
* Поиск корпоративных пакетов в публичных репозиториях

**Анализ CI/CD:**
* Проверка файлов .github/workflows
* Поиск опасных разрешений и секретов

**Проверка контейнеров:**
* Использование Trivy для сканирования образов
* Анализ Dockerfile на опасные команды

## Методы защиты
**Управление зависимостями:**
* Фиксация версий вместо "latest"
* Регулярный аудит зависимостей
* Использование приватных репозиториев

**Безопасность CI/CD:**
* MFA для доступа
* Минимальные права
* Защита секретов через переменные

**Контроль контейнеров:**
* Сканирование образов перед деплоем
* Использование минимальных базовых образов
* Цифровая подпись образов

**Дополнительные меры:**
* Внедрение SBOM (список компонентов)
* Автоматическое сканирование на уязвимости
* Контроль процесса обновления
* Использование инструментов SCA (Software Composition Analysis)

## Ключевые инструменты
* npm audit, pip-audit — аудит зависимостей
* Trivy — сканирование контейнеров
* Snyk — анализ состава ПО
* Gitleaks — поиск секретов
* Dependabot — мониторинг обновлений
