# Краткое руководство по уязвимостям контроля доступа

## **Основные типы уязвимостей**
* **Вертикальная эскалация** — получение доступа к функциям с повышенными привилегиями
* **Горизонтальная эскалация** (IDOR) — доступ к чужим данным при сохранении своего уровня доступа
* **Многоэтапные уязвимости** — обход проверок в сложных процессах

## **Способы обнаружения**

**Вертикальные уязвимости:**
* Поиск административных URL через:
  * Анализ robots.txt
  * Словарный перебор (Wordlist)
  * Изучение JavaScript-кода
* Проверка параметров в URL/cookie на возможность изменения роли:
  ```
  GET /profile?role=admin
  ```
* Анализ HTTP-методов и их влияния на доступ:
  ```
  GET /admin/deleteUser (вместо запрещенного POST)
  ```
* Проверка обработки разных форматов URL
* Прямое обращение к админским URL без проверки прав:
  ```text
  GET /admin/deleteUser
  ```
**Горизонтальные уязвимости (IDOR):**
* Манипуляция ID в URL:
  * ```https://site.com/profile?id=123 → id=124```
  * Проверка GUID-идентификаторов
  * Использование предсказуемых ID
* Анализ перенаправлений на утечки данных
* Поиск прямых ссылок на объекты:
    ```
    GET /files/123.pdf → GET /files/124.pdf
    ```

## **Методы эксплуатации**

**Основные векторы атак:**
* Прямое изменение параметров в URL
* Манипуляция HTTP-заголовками (Referer, X-Original-URL)
* Обход через разные HTTP-методы
* Использование символьных особенностей URL
* Эксплуатация ошибок в многоэтапных процессах

## **Способы защиты**

**Технические меры:**
* Внедрение централизованной системы контроля доступа
* Запрет доступа по умолчанию с явным предоставлением прав
* Проверка прав на сервере, а не на клиенте
* Использование безопасных идентификаторов вместо числовых ID
* Внедрение контекстной проверки доступа

**Организационные меры:**
* Регулярный аудит прав доступа
* Тестирование на обход проверок
* Документирование политик доступа
* Проверка всех этапов многоэтапных процессов
* Запрет использования "безопасности через неизвестность"

**Ключевые принципы:**
* Не полагаться на скрытие URL как защиту
* Использовать единую систему контроля
* Явно определять разрешённые действия
* Регулярно проводить тестирование безопасности
* Внедрять принцип минимальных привилегий
