# File Upload Vulnerabilities
## 1. Что это такое?
`File Upload Vulnerabilities` — это группа уязвимостей, возникающих, когда веб-приложение принимает файлы от пользователя без достаточной валидации их имени, типа, содержимого или размера.

* **Главный риск**: Загрузка серверных скриптов (RCE) и полный захват сервера (Web Shell).
* **Другие риски**: DoS (переполнение диска), Path Traversal (перезапись системных файлов), Stored XSS (через SVG/HTML), XXE (через парсинг .docx/.xlsx).

## 2. Методы поиска (Тестирование и Анализ)
* Black-box / Pentest:
    * Фаззинг `расширений файла` и заголовка `Content-Type` через Burp Intruder/Repeater.
    * Проверка поддержки метода `PUT` с помощью OPTIONS-запросов.
    * Тестирование на Race Condition (условия гонки) путем `отправки больших файлов` или быстрой отправки `параллельных запросов`.
* White-box / Code Review:
    * Анализ кастомной (самописной) `логики валидации загрузок`.
    * Проверка конфигурационных файлов сервера (наличие .htaccess, web.config), которые могут позволить переопределить MIME-типы.
    * Поиск опасных функций, `сохраняющих файл во временную директорию` до окончания валидации.

## 3. Примеры уязвимостей с кодом
### Пример 1: Обход валидации по MIME-типу 
```Python
# Уязвимый код (доверяет заголовку клиента):
from flask import Flask, request
app = Flask(__name__)

@app.route('/upload', methods=['POST'])def upload_file():
    file = request.files['file']
    # УЯЗВИМОСТЬ: Проверяется только заголовок Content-Type, присланный браузером
    if file.content_type == 'image/jpeg':
        file.save(f"./uploads/{file.filename}")
        return "Файл загружен!"
    return "Разрешены только JPEG", 400
```
Вектор атаки: Атакующий отправляет файл `shell.php`, но перехватывает запрос в Burp и вручную меняет строку `Content-Type: application/x-php` на `Content-Type: image/jpeg`. Сервер доверяет этому и сохраняет скрипт.

### Пример 2: Обход черного списка и Path Traversal
```js
// Уязвимый код (черный список и отсутствие санитизации имени):
const express = require('express');
const app = express();

app.post('/upload', (req, res) => {
    let file = req.files.avatar;
    // УЯЗВИМОСТЬ 1: Ненадёжный чёрный список (пропускает .php5, .phtml)
    if (file.name.endsWith('.php')) {
        return res.status(400).send('Запрещено!');
    }
    // УЯЗВИМОСТЬ 2: Сохранение с оригинальным именем (Path Traversal)
    file.mv('./uploads/' + file.name); 
    res.send('Загружено');
});
```
Вектор атаки:
1. Использование альтернативного расширения: `shell.php5` или запутывание `shell.p.phphp`.
2. Path Traversal: Имя файла `../../etc/cron.d/malicious_job` перезапишет системный файл, если сервер не очищает путь.

## 4. Методы защиты (Рекомендации для разработчиков)
1. **Белый список расширений**: Разрешать строго определенные расширения (.jpg, .png), а не запрещать плохие (черные списки не работают).
2. **Рандомизация имен**: Хранить файлы под случайно сгенерированными именами (GUID/UUID) без сохранения оригинального расширения в исходном виде, чтобы исключить прямой вызов.
3. **MIME & Content Validation**: Проверять реальную `сигнатуру файла` (**Magic Bytes**, например, FF D8 FF для JPEG), а не заголовок `Content-Type`. Для защиты от полиглотов (код внутри метаданных) использовать пересборку изображений.
4. **Изоляция хранилища**:
    * `Отключать выполнение скриптов` в каталоге загрузок (через настройки Nginx/Apache или запрет прав на исполнение noexec).
    * **Хранить файлы вне корневой директории** веб-сервера (Web Root) или использовать выделенный S3-бакет/облачное хранилище.
5. **Безопасные фреймворки**: Использовать встроенные механизмы фреймворков для загрузки, чтобы избежать Race Conditions.
