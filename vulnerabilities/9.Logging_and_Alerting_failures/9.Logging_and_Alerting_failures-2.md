# Security Logging and Alerting Failures (OWASP A09:2025)
## 1. Что это такое?
`Security Logging and Alerting Failures` — это критический сбой в процессах сбора, анализа и реагирования на события безопасности. Данный недостаток делает систему «слепой». 

Приложение может содержать уязвимости (RCE, SQLi), но без адекватного логирования ИБ-команда не узнает об атаке вовремя и не сможет ответить на вопросы: Кто? Что? Когда? Из каких источников? Была ли атака успешной?

## 2. Методы поиска
* `Code Review` (Рецензирование кода): Проверка наличия блоков `try-catch/except`, в которых перехватываются ошибки, но не генерируются записи в журнал (пустые блоки или логирование без контекста безопасности). Проверка на отсутствие утечки чувствительных данных в логи.
* `Архитектурный анализ` (Threat Modeling): Анализ путей прохождения логов от контейнера/сервера до SIEM. Проверка покрытия логами критических бизнес-операций (**аутентификация**, **смена прав**, **финансовые транзакции**).
* `SAST/DAST тестирование`: Сканирование кода на предмет использования небезопасных или сырых функций логирования, а также динамическая проверка реакции системы на аномальные запросы.

## 3. Примеры уязвимостей с кодом
* Плохая практика (Vulnerable Code) - **В лог пишется конфиденциальная информация** (пароль в открытом виде), либо критическая ошибка скрывается без уведомления ИБ.
```Python
@app.route('/api/login', methods=['POST'])def login():
    username = request.form.get('username')
    password = request.form.get('password') # Утечка секрета!
    try:
        auth_service.authenticate(username, password)
    except Exception as e:
        # Пароль пишется в текстовый лог, а ИБ не получает алерт
        logger.error(f"Login failed for {username} with password {password}. Error: {e}") 
        return "Error", 401
```
```JavaScript
app.post('/api/login', (req, res) => {
    const { username, password } = req.body;
    // КРИТИЧЕСКАЯ ОШИБКА: Запись пароля в stdout/лог
    console.log(`User  ${username} tried to login with password: ${password}`); 
    res.status(401).send('Unauthorized');
});
```
* Хорошая практика (Secure Code)
Секреты вырезаны, **логируются только метаданные безопасности** (IP, статус, таймстемп).
```Python:
import datetime
@app.route('/api/login', methods=['POST'])def login():
    username = request.form.get('username')
    ip_address = request.remote_addr
    try:
        auth_service.authenticate(username, request.form.get('password'))
    except AuthenticationError:
        # Логируем только контекст инцидента безопасности без пароля
        security_logger.warning({
            "event": "authentication_failed",
            "username": username,
            "source_ip": ip_address,
            "timestamp": datetime.datetime.utcnow().isoformat()
        })
        # Здесь должен триггериться Alert в SIEM при превышении лимита попыток
        return "Unauthorized", 401
```
```JavaScript
app.post('/api/login', (req, res) => {
    const { username } = req.body;
    // Логируем только безопасные метаданные
    securityLogger.warn({
        event: 'auth_failed',
        user: username,
        ip: req.ip,
        timestamp: new Date().toISOString()
    });
    res.status(401).send('Unauthorized');
});
```

## 4. Методы защиты
1. **Полноценное логирование событий ИБ**: Фиксировать входы/выходы, ошибки авторизации, создание пользователей, смену прав, подозрительные вызовы API.
2. **Маскирование данных**: Исключить попадание в логи паролей, токенов (JWT), API-ключей и ПДн.
3. **Централизация и SIEM**: Использовать стек EFK/ELK (Filebeat -> Logstash -> Elasticsearch -> Kibana) или Loki+Grafana для агрегации логов в единую доверенную систему.
4. **Настройка Алертинга**: Реализовать правила оповещения для критических аномалий (например, 100+ ошибок авторизации с одного IP за минуту).
5. **Целостность журналов**: Защитить хранилища логов от модификации и удаления злоумышленником при компрометации приложения.
6. **Синхронизация времени**: Настроить NTP на всех серверах для корректного проведения расследований (Timeline атаки).
