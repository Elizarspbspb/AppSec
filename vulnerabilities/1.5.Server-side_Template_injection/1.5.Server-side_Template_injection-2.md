# Server-Side Template Injection (SSTI): Краткое руководство для AppSec специалиста

## Что такое SSTI?
**Server-Side Template Injection** — уязвимость, при которой злоумышленник может внедрить собственный код в шаблоны веб-приложения, который будет исполняться на сервере.

## Основные характеристики
* **Механизм работы**: внедрение пользовательского кода в шаблоны вместо обычных данных
* **Критичность**: высокая, может привести к RCE (удаленному выполнению кода)
* **Последствия**:
  * Чтение файлов на сервере
  * Утечка конфиденциальных данных
  * Выполнение системных команд
  * Полный контроль над сервером

## Как обнаружить уязвимость
**Методы тестирования**:
* Проверка базовых математических выражений: `{{7*7}}`
* Анализ поведения при вводе специальных символов: `${{<%[%'"}}%\`
* Проверка через XSS-подобные конструкции

**Контексты уязвимости**:
* **Простой контекст**: вставка в HTML-код
* **Кодовый контекст**: вставка в выражения шаблона

## Примеры атак
**Базовые проверки**:
```html
http://site.com/?param={{7*7}}
http://site.com/?param={{self}}
```

**Продвинутые техники**:
* Использование цепочек объектов
* Работа с системными классами
* Эксплуатация кастомных объектов приложения

## Способы защиты
**Основные меры**:
* **Правильная передача данных**:
  ```php
  // Правильно
  $output = $twig->render("template", array("param" => $user_input));
  
  // Неправильно
  $output = $twig->render($user_input);
  ```

* Использование безопасных шаблонизаторов (например, Mustache)
* Применение песочницы для изоляции выполнения
* Запуск шаблонизатора в изолированной среде

## Рекомендации по безопасности
* Никогда не вставляйте пользовательский ввод напрямую в шаблон
* Ограничьте возможности редактирования шаблонов
* Используйте параметризованный подход к передаче данных
* Регулярно обновляйте шаблонизатор
* Проводите аудит безопасности кода

## Пример правильного использования
```php
// Безопасный код
$template = "Привет, {{username}}!";
$data = array(
    "username" => sanitize_input($_GET['username'])
);
$output = $twig->render($template, $data);
```

## Ключевые моменты для запоминания
* SSTI — это инъекция кода в серверные шаблоны
* Уязвимость возникает при прямой вставке пользовательского ввода в шаблон
* Защита строится на правильном разделении кода и данных
* Даже без RCE уязвимость остается опасной

# ПЕРЕСКАЗ 
---
## 1. Что такое Server-side template injection (SSTI)
**SSTI** — уязвимость, при которой злоумышленник может внедрить собственный код в шаблон, который затем выполняется сервером.

## 2. Что такое шаблоны?
**Шаблонизатор** — инструмент для генерации HTML-страниц. Пример шаблона:
```html
<h1>Привет, {{ username }}!</h1>
```
При подстановке значения "Ivan" сервер создаст:
```html
<h1>Привет, Ivan!</h1>
```

## 3. Главное отличие SSTI от Client-Side Template Injection
**Client-Side** выполняется в браузере, **Server-Side** — на сервере. SSTI опаснее, так как позволяет воздействовать на само серверное приложение.

## 4. Каковы последствия Server-Side Template Injection?
* **RCE** (удалённое выполнение кода)
* Чтение внутренних переменных
* Доступ к конфигурационным файлам
* Извлечение секретных ключей
* Просмотр файлов на сервере

## 5. Почему возникает SSTI?
Основная причина — вставка пользовательского ввода прямо в шаблон вместо передачи как данных.

**Неправильный код:**
```php
$output = $twig->render("Dear " . $_GET['name']);
```

**Правильный код:**
```php
$output = $twig->render(
    "Dear {{ first_name }}",
    array("first_name" => $user->first_name)
);
```

## 6. Как строится атака на SSTI
1. Обнаружение уязвимости
2. Определение типа шаблонизатора
3. Подбор метода эксплуатации

## 7. Как проверить наличие SSTI
* Вставить тестовые символы: `${{<%[%'"}}%\`
* Проверить реакцию сервера
* Протестировать математические выражения: `${7*7}`

## 8. Определение шаблонизатора (Identify)
* Анализ ошибок:
```py
# Пример вызова ошибки для определения ERB
<%= foobar %> 
# Результат: NameError: undefined local variable 'foobar'
```
* Тестирование различных синтаксисов:
```py
# Проверка разных синтаксисов для определения движка
{{7*'7'}}  # Результат может быть разным для разных движков
```
* Изучение поведения выражений:
```py
# Тестирование математических операций
{{7*7}}    # Проверка базового функционала
```

## 9. Эксплуатация (Exploitation)
* Исследование доступных объектов:
```java
# Пример исследования окружения в Velocity
$class.inspect("java.lang.Runtime").type
```
* Поиск цепочек методов:
```java
# Пример цепочки вызовов
$class.inspect("java.lang.Runtime").type.getRuntime().exec("command")
```
* Построение payload:
```java
# Пример построения эксплойта
#set($str=$class.inspect("java.lang.String").type)
#set($chr=$class.inspect("java.lang.Character").type)
#set($ex=$class.inspect("java.lang.Runtime").type.getRuntime().exec("whoami"))
```

## 10. Использование уязвимостей инъекций шаблонов на стороне сервера
* Изучение документации шаблонизатора:
```py
# Пример использования документации
import os
x = os.popen('id').read()
```
* Поиск доступных объектов:
```py
# Пример доступа к системным объектам
{{self}}
{{environment}}
```
* Построение эксплойта:
```py
# Пример построения атаки
{{T(java.lang.System).getenv()}}
```

## 11. Как защититься от Server-Side Template Injection (SSTI)
* Не позволять пользователям создавать шаблоны:
```py
# Правильный способ передачи данных
render("Dear {{name}}", {"name": user_name})
```
* Использовать шаблонизаторы без логики:
```mustache
<!-- Пример Mustache шаблона -->
<h1>Привет, {{name}}!</h1>
```
* Применять песочницу:
```py
# Настройка песочницы для шаблонов
template.sandbox = True
```
* Изолировать процесс выполнения шаблонов:
```dockerfile
# Пример изоляции в Docker
FROM python:3.9-slim
RUN pip install -r requirements.txt
```

## 12. Основные рекомендации по защите
* Передавать пользовательский ввод только как данные:
```py
# Безопасный способ
render(template, {"user_input": sanitized_data})
```
* Ограничить редактирование шаблонов:
```py
# Проверка прав доступа
if user.is_admin:
    allow_template_editing()
```
* Использовать Mustache-подобные шаблонизаторы:
```mustache
<!-- Только подстановка данных -->
{{user.name}}
```
* Включать песочницу при необходимости:
```py
# Активация защитного режима
engine.enable_sandbox()
```
* Изолировать выполнение шаблонов в контейнерах:
```yaml
# Пример конфигурации Docker-compose
version: '3'
services:
  template-renderer:
    image: template-engine
    container_name: template_renderer
    restart: always
    security_opt:
      - no-new-privileges:true
```
