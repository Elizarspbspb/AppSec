# Краткое руководство по уязвимостям OAuth 2.0
## Что такое OAuth 2.0
`OAuth 2.0` — протокол авторизации, позволяющий приложениям получать ограниченный доступ к данным пользователя в других сервисах без передачи паролей. Используется для входа через соцсети и интеграции с внешними сервисами.

## Основные типы уязвимостей
* **Утечка токенов доступа** через браузер при использовании Implicit Grant
* **CSRF-атаки** из-за отсутствия или неправильной реализации параметра state
* **Подмена redirect_uri** для перехвата кодов авторизации
* **Расширение scope** без согласия пользователя
* **Кража кодов авторизации** через открытые редиректы

## Способы обнаружения
**Поиск в коде:**
* Проверьте наличие параметра ```state``` в запросах авторизации
* Проанализируйте валидацию ```redirect_uri```
* Ищите небезопасную обработку ```access_token``` в клиентском коде
* Проверьте регистрацию ```client_id``` и ```client_secret```

**Примеры атак:**
```http
GET /authorize?client_id=123&redirect_uri=evil.com  // Подмена redirect_uri
GET /callback#access_token=token123                 // Implicit Grant утечка
POST /token?code=authcode&client_id=123             // Кража кода авторизации
```

## Методы защиты
**На стороне сервера:**
* Строгая проверка ```redirect_uri``` (полное совпадение)
* Обязательное использование параметра ```state```
* Внедрение механизма **PKCE** для мобильных приложений
* Валидация ```scope``` при обмене токена
* Хранение ```client_secret``` в безопасном хранилище

**На стороне клиента:**
```python
# Пример правильной обработки OAuth
def authorize():
    state = generate_random_state()
    redirect_uri = "https://app.com/callback"
    return f"/authorize?client_id={client_id}&redirect_uri={redirect_uri}&state={state}"

def callback(code, state):
    if not validate_state(state):
        raise Exception("Invalid state")
    token = exchange_code(code, redirect_uri)
    return token
```

## Дополнительные меры
* Используйте **Authorization Code Grant** вместо Implicit
* Регулярно обновляйте токены доступа
* Проверяйте целостность ```id_token``` при использовании OpenID Connect
* Ограничьте время жизни ```state``` и ```code_verifier```
* Применяйте `CSP` для защиты от XSS-атак

**Критически важно:** Никогда не храните токены в локальном хранилище браузера и не передавайте их в URL как параметры запроса.
