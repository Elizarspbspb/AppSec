# Уязвимости API
## 1. Что такое уязвимости API?
`Уязвимости API` — это недостатки проектирования, реализации или конфигурации интерфейсов взаимодействия программ. Они нарушают триаду CIA (конфиденциальность, целостность, доступность) веб-ресурсов. 

Специфика API заключается в автоматизированном массовом обмене данными, из-за чего классические веб-атаки (например, инъекции) здесь масштабируются, а ошибки логики и разграничения прав доступа (OWASP API Security Top 10) выходят на первый план.

## 2. Методы поиска уязвимостей API
Поиск (разведка) делится на три ключевых этапа:
* **Поиск документации и базовых путей**: Поиск эндпоинтов (Swagger, OpenAPI, RAML) через фаззинг путей (например, `/swagger/index.html`, `/api/openapi.json`) с помощью Burp Intruder.
* **Анализ трафика** и JS-файлов: Выявление скрытых эндпоинтов в клиентских скриптах с помощью расширения `JS Link Finder`, а также `фаззинг методов HTTP` (GET, POST, PATCH, OPTIONS) и `типов данных` (Content-Type: application/xml вместо json для поиска XXE).
* **Поиск скрытых параметров**: Использование утилит `Param Miner` и `Content Discovery` для перебора параметров, способных влиять на бизнес-логику.

## 3. Пример уязвимости: Массовое присваивание 
Возникает, когда фреймворк автоматически привязывает (bind) все параметры входящего запроса к полям бизнес-объекта в базе данных, позволяя злоумышленнику перезаписать скрытые свойства (например, is_admin, role).
```Python
# Принимает любой JSON и сразу обновляет модель пользователя
@app.route('/api/user/update', methods=['PATCH'])def update_user():
    user_data = request.get_json()
    # Уязвимость: если атакующий передаст {"is_admin": true}, поле перезапишется
    User.query.filter_by(id=current_user.id).update(user_data)
    db.session.commit()
    return jsonify({"status": "success"})
```
```JS
// Автоматическое сохранение всего тела запроса в базу данных
router.patch('/api/profile', async (req, res) => {
    // Уязвимость: req.body может содержать строго защищенные поля вроде { "role": "admin" }
    await User.update(req.body, { where: { id: req.user.id } });
    res.json({ message: "Updated successfully" });
});
```
## 4. Методы защиты (Рекомендации для исправления)
* Защита от Mass Assignment (Data Transfer Object / Whitelisting): **Жестко ограничить список полей**, которые разрешено обновлять пользователю через API.
* **Контроль методов и типов данных**: Явно разрешать только легитимные HTTP-методы для каждой конечной точки, строго валидировать заголовок Content-Type и структуру входящих схем (JSON Schema/XML Schema).
* **Безопасная обработка ошибок**: Использовать только `общие (generic) сообщения об ошибках`. Запретить вывод `stack trace` и системной информации вовне.
* **Управление инвентаризацией**: Контролировать версионирование API (блокировать старые/неиспользуемые ветки) и ограничивать публичный доступ к Swagger/OpenAPI спецификациям в production-среде.

```py
# Исправление через Whitelisting
@app.route('/api/user/update', methods=['PATCH'])
def update_user_safe():
    user_data = request.get_json()
    # Разрешаем изменять только безопасные поля
    allowed_fields = {k: v for k, v in user_data.items() if k in ['username', 'email']}
    User.query.filter_by(id=current_user.id).update(allowed_fields)
    db.session.commit()
    return jsonify({"status": "success"})
```
