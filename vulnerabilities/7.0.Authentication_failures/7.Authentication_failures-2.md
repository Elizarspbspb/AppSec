# Authentication Failures: Краткое руководство для AppSec специалиста

## Что такое Authentication Failures?
**Authentication Failures** — класс уязвимостей в механизмах аутентификации и управления сессиями, позволяющий злоумышленнику получить несанкционированный доступ к системе.

## Основные типы атак
1. **Перебор учетных данных**
* User enumeration: различающиеся сообщения об ошибках при вводе логина
```
Логин: admin → "Неверный пароль"
Логин: ivan123 → "Пользователь не найден"
```
* Password enumeration: отсутствие ограничений на количество попыток

2. **Атаки на OAuth/OpenID**
* Подмена **redirect_uri** в OAuth-авторизации
```
https://evil.com/callback вместо легитимного адреса
```

3. **Манипуляции с сессиями**
* Session Hijacking (перехват сессии)
* Session Fixation (фиксация сессии)
* Session Prediction (предсказание ID сессии)

4. **Атаки на JWT**
* Изменение алгоритма подписи (alg: none)
* Подбор секретного ключа
* Использование устаревших токенов

5. **Хранение паролей в открытом виде**
* Отсутствие хеширования паролей в БД

## Способы защиты
1. **Базовая защита**
* Использование стойких алгоритмов хеширования (bcrypt, Argon2)
* Многофакторная аутентификация (MFA)
* Ограничение количества попыток входа

2. **Защита сессий**
* Генерация криптостойких session ID
* Использование флагов cookies (HttpOnly, Secure, SameSite)
* Ограничение времени жизни сессий

3. **Защита JWT**
* Запрет небезопасных алгоритмов
* Сложные секретные ключи
* Ограничение времени жизни токенов

4. **Защита от CSRF**
* Использование CSRF-токенов
* Настройка SameSite для cookies
* Правильная конфигурация CORS
```javascript
app.use(cors({
    origin: "https://example.com",
    methods: ["GET", "POST"],
    credentials: true
}));
```

## Ключевые моменты для запоминания
* Всегда использовать HTTPS
* Запретить хранение паролей в открытом виде
* Внедрить механизмы блокировки аккаунтов
* Использовать строгую политику управления сессиями
* Регулярно проводить аудит механизмов аутентификации
