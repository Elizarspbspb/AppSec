## Краткое руководство по SQL-инъекциям

## 1. Что такое SQL-инъекция
**SQL-инъекция** — уязвимость, позволяющая злоумышленнику вмешиваться в SQL-запросы приложения для:
* Получения несанкционированного доступа к данным
* Изменения или удаления информации
* Обхода аутентификации

## 2. Основные типы уязвимостей
* **Классические инъекции** — прямое внедрение кода через пользовательский ввод
* **Слепые инъекции** — без прямого вывода данных
* **Инъекции второго порядка** — через сохраненные данные
* **Внеполосные атаки OAST** — через сторонние каналы (DNS, HTTP)

## 3. Способы обнаружения
**Ручной поиск**:
* Тестирование кавычками `'`
* Проверка булевых условий `OR 1=1`
* Анализ временных задержек
* Использование Burp Scanner

**Примеры тестирования**:
```sql
' -- базовая проверка
' OR 1=1 -- обход условий
' UNION SELECT -- извлечение данных
' WAITFOR DELAY -- временные задержки
```

## 4. Эксплуатация уязвимостей
**Основные векторы атак**:
* Извлечение данных через UNION
* Обход аутентификации
* Получение структуры БД
* Выполнение произвольных запросов

**Базовые атаки:**
```text
https://site.com?param=value'--  // Простейшая инъекция
https://site.com?param=value' OR 1=1-- // Обход условий
https://site.com?param=value' UNION SELECT ...  // Получение данных из других таблиц
```
**Слепые инъекции:**
```text
payload = ' AND SLEEP(10)  // Временная задержка
payload = ' AND (SELECT 1 FROM users WHERE ...) // Условная проверка
```
## 5. Методы защиты
**Параметризованные запросы**:
```python
# Уязвимый код
query = "SELECT * FROM users WHERE username = '" + username + "'"
# Защищенный код
stmt = "SELECT * FROM users WHERE username = ?"
cursor.execute(stmt, (username,))
```

**Белый список для небезопасных частей SQL**:
```python
allowed_columns = {
    "price": "price",
    "name": "name",
    "date": "created_at"
}
if sort in allowed_columns:
    column = allowed_columns[sort]
    cursor.execute(f"SELECT * FROM products ORDER BY {column}")
```

## 6. Когда нельзя использовать параметры
* При работе с именами таблиц
* В операторах `ORDER BY`
* При динамическом построении структуры запроса

В этих случаях используйте:
* Строгий белый список допустимых значений
* Санкционирование входных данных
* Статический SQL-шаблон

### Ключевые моменты защиты
* Никогда не конкатенируйте пользовательский ввод напрямую в запрос
* Используйте параметризованные запросы для данных
* Применяйте белый список для синтаксических элементов
* Валидируйте все входные данные
* Ограничивайте права доступа к БД
