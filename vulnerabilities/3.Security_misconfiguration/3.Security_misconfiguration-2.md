# Security Misconfiguration: Краткое руководство для AppSec специалиста

## Что такое Security Misconfiguration
**Security Misconfiguration** — уязвимость, возникающая из-за неправильной настройки компонентов системы (ОС, веб-сервера, БД, облачных сервисов). В отличие от программных ошибок, появляется из-за некорректной конфигурации.

## Основные типы уязвимостей
* **Стандартные учетные данные**: admin/admin, root/root
* **Отладочные функции**: /debug, /phpinfo.php, /swagger
* **Открытые порты**: SSH, FTP, Redis без аутентификации
* **Неправильные права доступа**: доступные .env, backup.zip, logs/
* **Отсутствие шифрования**: HTTP вместо HTTPS
* **Неправильная CORS-настройка**: Access-Control-Allow-Origin: *
* **Детализированные ошибки**: раскрытие стека, версий ПО
* **Устаревшее ПО**: старые версии Apache, Nginx, PHP

## Способы поиска уязвимостей
* Сканирование директорий: /admin, /backup, .git, .env
* Анализ HTTP-заголовков: Server, X-Powered-By, CORS
* Проверка открытых портов и сервисов
* Поиск утечек информации через ошибки
* Анализ конфигурации SSL/TLS
* Проверка версий компонентов

## Примеры атак
**CORS-атака**:
```
GET /api/profile HTTP/1.1
Origin: https://evil.com

// Ответ сервера:
Access-Control-Allow-Origin: https://evil.com
Access-Control-Allow-Credentials: true
```

**Утечка информации**:
```
GET /product?id='
// Ответ с утечкой:
SQLSTATE[42000]: SELECT * FROM products WHERE id=''
```

## Методы защиты
* **Базовая конфигурация**:
  * Удаление стандартных учетных записей
  * Отключение отладочных функций
  * Закрытие неиспользуемых портов

* **Правильные настройки**:
```python
# CORS конфигурация
CORS_ORIGINS = ['example.com']

# HTTPS настройка
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
```

* **Контроль доступа**:
```bash
# Права на файлы
chmod 600 .env
chmod 755 backup
```

* **Регулярные проверки**:
  * Аудит конфигурации
  * Сканирование на уязвимости
  * Обновление ПО
  * Мониторинг безопасности

## Ключевые рекомендации
* Использовать HTTPS с TLS 1.2/1.3
* Минимизировать поверхность атаки
* Настраивать CORS только для доверенных источников
* Отключать режим отладки в продакшене
* Регулярно обновлять все компоненты системы
* Внедрить автоматизированный контроль конфигурации
