# NoSQL Injection: Краткое руководство для AppSec специалиста

## Что такое NoSQL Injection?
**NoSQL Injection** — уязвимость, позволяющая внедрять вредоносный код в запросы к базам данных NoSQL через пользовательский ввод. Злоумышленник может манипулировать запросами для:
* Обхода аутентификации
* Получения несанкционированного доступа к данным
* Изменения или удаления данных
* Выполнения произвольного кода

## Основные типы атак
1. **Синтаксическая инъекция** — нарушение структуры запроса через специальные символы
2. **Операторная инъекция** — внедрение специальных операторов запросов (например, `$ne`, `$or`, `$regex`)
3. **JavaScript-инъекция** через операторы `$where` и `mapReduce()`

## Способы обнаружения
* **Тестирование ввода**:
  * Отправка специальных символов и fuzz-строк
  * Проверка обработки операторов
  * Анализ изменений в ответах сервера

* **Примеры атак**:
```json
// Обход аутентификации
{"username":{"$ne":"invalid"},"password":{"$ne":""}}

// Временная инъекция
{"$where":"sleep(5000)"}

// Извлечение данных
{"username":"admin' && this.password[0] == 'a'"}
```

## Методы защиты
1. **Валидация ввода**:
* Использование белых списков допустимых символов
* Экранирование специальных символов
* Проверка формата данных

2. **Безопасные практики**:
* Использование параметризованных запросов
* Ограничение прав доступа к БД
* Применение ORM/ODM-библиотек

3. **Технические меры**:
* Фильтрация операторов запросов
* Проверка схемы данных
* Установка таймаутов для запросов

4. **Мониторинг**:
* Логирование запросов
* Анализ подозрительной активности
* Настройка оповещений

## Примеры безопасной реализации
```javascript
// Неправильно
db.users.find({ username: req.body.username })

// Правильно
const query = { 
  username: sanitizeInput(req.body.username),
  $and: allowedOperators
}
db.users.find(query)
```

## Ключевые моменты для запоминания
* NoSQL не использует SQL-синтаксис, каждая БД имеет свой язык запросов
* Уязвимость часто возникает при прямой конкатенации пользовательского ввода
* Защита строится на комбинации валидации, параметризации и контроля доступа

# ПЕРЕСКАЗ
---
## 1. Чем NoSQL отличается от SQL?
**NoSQL** отличается от SQL следующими характеристиками:
* Формат хранения: вместо таблиц используются гибкие структуры (документы, ключ-значение, графы)
* Языки запросов: нет единого стандарта, каждая система имеет свой синтаксис
* Меньше ограничений: не требует строгой схемы данных и связей между таблицами

## 2. Базы данных NoSQL
Основные преимущества:
* Работа с неструктурированными данными
* Высокая масштабируемость
* Гибкость в изменении структуры
* Производительность при больших потоках данных

## 3. Как с ними работать?
Взаимодействие происходит через:
* Специальный API
* Собственный язык запросов
* Форматы JSON/XML

## 4. Модели баз данных NoSQL
Основные типы:
* **Документо-ориентированные** (MongoDB, Couchbase) - хранят данные в JSON/BSON
* **Ключ-значение** (Redis, DynamoDB) - простая структура ключ-значение
* **Колоночные** (Cassandra, HBase) - гибкие семейства колонок
* **Графовые** (Neo4j, Neptune) - хранение связей между объектами

## 5. Типы инъекций NoSQL
Основные виды:
* **Синтаксическая инъекция** - нарушение структуры запроса
* **Инъекция операторов** - использование специальных операторов запросов

## 6. NoSQL-синтаксическая инъекция
**Пример уязвимости:**
```javascript
// Исходный запрос
{ "username": "user_input" }

// Злоумышленный ввод
"admin" , "$ne": ""
```
**Обнаружение:**
* Тестирование специальными символами
* Анализ изменений в ответах сервера

## 7. NoSQL-инъекция через операторы
**Пример с оператором $ne:**
```json
{
  "username": {
    "$ne": "invalid"
  }
}
```
Оператор `$ne` (not equal) позволяет найти все записи, где значение не равно указанному. Злоумышленник может использовать это для обхода аутентификации. 

**Пример атаки:** если ввести `{"username": {"$ne": ""}}`, запрос вернёт первого найденного пользователя.

**Риск:** полный обход системы аутентификации.

## 8. JavaScript-инъекции
**Пример эксплойта:**
```javascript
'admin' && this.password[0] == 'a' || 'a'=='b'
```
Выполнение произвольного JavaScript кода через инъекцию. Позволяет проверять условия посимвольно. **В примере** проверяется, начинается ли пароль администратора с буквы `'a'`.

**Риск:** постепенное раскрытие конфиденциальных данных. Может использоваться для: проверки длины пароля, определения типа данных, получения структуры БД

## 9. Эксплуатация операторов
**Использование $regex:**
```json
{
  "password": {
    "$regex": "^a.*"
  }
}
```
Использование регулярных выражений для поиска данных. Позволяет: проверять начало пароля, искать определённые символы, определять длину пароля.

**Риск:** постепенное раскрытие паролей и других данных. Может комбинироваться с другими типами инъекций.

## 10. Временная инъекция
**Пример задержки:**
```javascript
function(x){
  if(x.password[0]=="a"){sleep(5000)};
}(this)
```
Использование задержки выполнения для проверки условий. Позволяет: проверять истинность условий, извлекать данные посимвольно, обходить системы защиты.

**Риск:** скрытый способ извлечения данных. Обнаруживается по аномальному времени ответа.

## 11. Предотвращение инъекций
Основные методы защиты:
* Валидация и фильтрация ввода:
```javascript
// Разрешительный список символов:
// Пример валидации для логина
function validateUsername(input) {
    const regex = /^[a-zA-Z0-9_]+$/;
    return regex.test(input);
}
// Пример использования
const username = req.body.username;
if (!validateUsername(username)) {
    throw new Error('Invalid username');
}
```
* Использование параметризованных запросов:
```js
// Неправильно (уязвимо):
const query = { username: req.body.username };

// Правильно (защищено):
const sanitizedInput = sanitizeInput(req.body.username);
const query = { username: sanitizedInput };
```
* Ограничение разрешенных ключей:
```js
// Белый список полей:
const allowedKeys = ['username', 'password', 'email'];
...
function validateQuery(input) {
    return Object.keys(input).every(key => allowedKeys.includes(key));
}
// Пример проверки:
const userInput = { username: 'test', password: 'pass' };
if (!validateQuery(userInput)) {
    throw new Error('Invalid query keys');
}
```
* Настройка минимальных привилегий:
```javascript
// Пример конфигурации прав:
// Настройки подключения к БД
const dbConfig = {
    user: 'app_user',
    permissions: {
        read: true,
        write: true,
        executeJS: false,
        eval: false
    }
};
```
* Применение ORM/ODM библиотек:
```js
// Использование Mongoose:
// Определение схемы
const userSchema = new mongoose.Schema({
    username: { type: String, required: true },
    password: { type: String, required: true }
});
// Создание модели
const User = mongoose.model('User', userSchema);
// Безопасный запрос
User.find({ username: req.body.username });
```
* Мониторинг подозрительных запросов:
```js
// Пример логирования:
function logQuery(query) {
    // Проверка на опасные операторы
    if (query.$where || query.$regex) {
        console.log('Подозрительный запрос:', query);
    }
    // Запись в журнал
    auditLog.add({
        query: JSON.stringify(query),
        timestamp: new Date()
    });
}
// Использование:
const query = buildQuery(req.body);
logQuery(query);
db.collection.find(query);
```
