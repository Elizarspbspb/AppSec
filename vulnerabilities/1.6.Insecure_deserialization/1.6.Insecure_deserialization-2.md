# Небезопасная десериализация: краткое руководство для AppSec специалиста

## Что такое небезопасная десериализация
**Десериализация** — процесс восстановления объекта из последовательности байтов/текста. **Небезопасная десериализация** возникает при восстановлении объектов из недоверенных данных, что позволяет атакующему манипулировать типами объектов и их поведением, вплоть до RCE.

## Основные признаки уязвимости
* Наличие функций десериализации в коде:
  * PHP: `unserialize()`
  * Java: реализация `Serializable`
  * Python: `pickle`
* Характерные сигнатуры в данных:
  * PHP: формат `O:4:"User":2:{...}`
  * Java: начало `ac ed` (hex) или `rO0` (base64)
* Передача сериализованных данных через:
  * Cookies
  * Параметры запроса
  * Тело HTTP-запроса

## Способы эксплуатации
* **Модификация существующих объектов**: изменение полей (например, `isAdmin` с false на true)
* **Инъекция объектов**: подмена типа объекта для вызова неожиданных методов
* **Цепочки гаджетов**: построение последовательности вызовов опасных методов
* **PHAR-десериализация** в PHP через обёртки файлов

## Примеры атак
* PHP: изменение сериализованной строки в cookie
```php
O:4:"User":2:{s:8:"username";s:6:"carlos";s:7:"isAdmin";b:1;}
```
* Java: использование инструментов типа ysoserial для генерации payload

## Методы защиты
* **Полное исключение**: по возможности не десериализовать пользовательские данные
* **Проверка целостности**:
  * Цифровая подпись данных
  * Хеширование перед сериализацией
* **Безопасная десериализация**:
  * Создание собственных методов десериализации
  * Проверка типа объекта до десериализации
  * Контроль восстанавливаемых полей
* **Ограничения**:
  * Запрет десериализации определённых классов
  * Использование белых списков разрешённых типов

## Ключевые моменты для аудита
* Поиск функций десериализации в коде
* Анализ мест передачи сериализованных данных
* Проверка наличия механизмов защиты
* Контроль за использованием сторонних библиотек с сериализацией

## Что НЕ работает
* Проверка после десериализации
* Фильтрация известных гаджетов
* Опора на бинарные форматы как защиту
* Блокировка только известных уязвимостей

# ПЕРЕСКАЗ

## 1. Что такое сериализация?
**Сериализация** — процесс преобразования объекта в простой формат для передачи или хранения. При этом сохраняется состояние объекта со всеми значениями полей.

## 2. Сериализация и десериализация
**Десериализация** — обратный процесс восстановления объекта из сохраненного формата. После восстановления объект можно использовать как до сериализации.

## 3. Что такое небезопасная десериализация?
**Небезопасная десериализация** возникает при восстановлении объектов из недоверенных данных, что позволяет атакующему влиять на типы объектов и их поведение.

## 4. Как возникают уязвимости
Основные причины:
* Десериализация пользовательских данных без проверки
* Попытка "защититься" проверками после десериализации
* Недооценка рисков бинарных форматов
* Сложность контроля зависимостей в современных приложениях

## 5. Последствия
* **RCE** (удалённое выполнение кода)
* Повышение привилегий
* Доступ к файлам
* Отказ в обслуживании

## 6. Как использовать уязвимости

### 6.1 Определение уязвимости
Признаки в PHP:
```php
O:4:"User":2:{s:4:"name":s:6:"carlos";s:10:"isLoggedIn":b:1;}
```

В Java:
```
ac ed (hex) или rO0 (Base64)
```

### 6.2 Манипулирование объектами
Пример изменения атрибута:
```php
// Исходный объект
O:4:"User":2:{s:8:"username";s:6:"carlos";s:7:"isAdmin";b:0;}

// После модификации
b:0 → b:1 (пользователь становится админом)
```

### 6.3 Использование функций приложения
Атакующий может подменить пути к файлам или другие параметры, используемые в опасных операциях.

### 6.4 Инъекции объектов
Возможность подмены типа объекта для вызова неожиданных методов.

### 6.5 Цепочки гаджетов
Используются готовые инструменты:
* **ysoserial** для Java
* **PHPGGC** для PHP

### 6.6 Создание эксплойта
Включает:
* Поиск магических методов
* Анализ цепочек вызовов
* Формирование payload

### 6.7 PHAR-десериализация
Эксплуатация через:
* phar:// обёртки
* Автоматическую десериализацию метаданных

### 6.8 Уязвимости памяти
Использование багов в функциях десериализации.

## 6.9 Предотвращение уязвимостей
Основные меры:
* Не десериализовать данные от пользователя
* Проверять целостность до десериализации
* Использовать собственные безопасные форматы
* Минимизировать автоматическую сериализацию
* При необходимости использовать цифровую подпись
