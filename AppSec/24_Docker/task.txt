Нужно взять любой свой небольшой проект (вообще любой учебный/личный) и:





упаковать его в Docker-образ с помощью Dockerfile,



запустить контейнер,



убедиться, что приложение работает внутри контейнера.

Тип проекта может быть любым, например:





маленькое веб-приложение (Flask / Django / FastAPI / Node / PHP и т.п.),



консольный скрипт,



простое API,



даже статический сайт на Nginx (если вам так удобнее).

Главное — чтобы запуск через Docker был осмысленный и воспроизводимый.

 

Что нужно сделать





Выбрать проект





Возьмите любой свой небольшой проект, который не слишком сложный (лучше что-то минимальное для первого опыта).



Написать Dockerfile

В корне проекта создайте файл Dockerfile, который:





использует подходящий базовый образ (например, с нужным языком),



копирует внутрь контейнера исходный код,



устанавливает зависимости (если они есть),



задаёт команду запуска приложения (CMD или ENTRYPOINT),



при необходимости открывает нужный порт (EXPOSE), если это веб-приложение.



Собрать Docker-образ





Соберите образ на основе вашего Dockerfile.



Дайте образу осмысленный тег.



Запустить контейнер





Запустите контейнер из собранного образа.



Если у вас веб-приложение:





пробросьте порт, чтобы можно было открыть его в браузере (например, localhost:8080 или другой).



Если консольное приложение:





покажите, что оно отрабатывает успешно внутри контейнера (вывод в терминал).



Проверить работу





Для веб-приложения — открыть страницу в браузере и убедиться, что всё работает.



Для CLI-приложения — показать вывод работы скрипта из контейнера.



Что сдать

Один файл (PDF или DOCX), в котором есть:





Краткое описание проекта
3–5 предложений:





что делает ваше приложение;



на каком языке написано;



как оно обычно запускается без Docker.



Текст Dockerfile





Вставьте содержимое файла Dockerfile целиком.



В 2–4 предложениях объясните:





какой базовый образ выбрали и почему;



какую команду запуска (CMD / ENTRYPOINT) используете.



Список основных Docker-команд, которые вы использовали

Например:





команда сборки образа;



команда запуска контейнера;



по желанию — команда для просмотра контейнеров / логов.

Не нужно расписывать всё, только ключевые команды, которые реально использовали.





Скриншоты





Скриншот успешной сборки образа (терминал).



Скриншот списка контейнеров/образов или вывода работающего приложения в терминале.



Если у вас веб-приложение:





скриншот страницы в браузере, показывающей, что приложение работает внутри контейнера (желательно, чтобы в кадр попадала строка адреса).



Короткий вывод (3–5 предложений)

Ответьте на вопросы:





что было самым сложным при создании Dockerfile;



в чём преимущество запуска приложения в контейнере по сравнению с «голым» запуском;



как вы могли бы использовать Docker в других своих проектах (даже кратко и на уровне идей).

 

Требования к зачёту





Есть рабочий Dockerfile, который можно использовать для сборки образа.



Образ успешно собирается и контейнер запускается.



Приложение внутри контейнера реально работает (видно по выводу или по открывающейся странице).



В отчёте:





есть Dockerfile,



перечислены Docker-команды, которые вы использовали,



приложены скриншоты сборки/запуска/работы.

 На «отлично»





Осмысленное имя образа (а не latest без названия).



В Dockerfile есть минимальная забота об «аккуратности» (например, установка зависимостей через один слой, а не хаос).



В выводе вы коротко отмечаете, что бы вы улучшили дальше (например, уменьшить размер образа, использовать alpine, разделить dev/prod и т.п.).

 





Подсказки







В качестве проекта можно взять вообще минимальный пример (например, маленький Flask-«Hello, world»), если других проектов нет.



Типовой подход:





выбрать базовый образ с нужным языком/рантаймом;



скопировать файлы проекта внутрь;



установить зависимости (если есть);



прописать команду запуска.



Если вы не помните точный синтаксис команд сборки/запуска, посмотрите шпаргалку или лекцию по Docker, но не копируйте все примеры без понимания — вам пригодится умение собрать образ под свой проект.
