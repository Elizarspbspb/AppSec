# Основы HTML и CSS
Понимание структуры и поведения клиентской стороны — обязательная часть знаний специалиста по безопасности приложений (AppSec).

Почему? Потому что многие уязвимости рождаются именно на стороне клиента:
* `XSS` (Cross-Site Scripting - внедрение вредоносного JavaScript-кода в страницу, выполняющегося у пользователя)
* `Clickjacking` (обман, при котором пользователь кликает по скрытым элементам на странице, встроенной в чужой сайт)
* `Уязвимости в формах ввода` (ошибки, позволяющие злоумышленнику отправить или подменить данные например, через непроверенные поля форм)
* `Небезопасные JavaScript-скрипты` (скрипты, которые можно изменить, подменить или использовать для кражи данных например, из внешних источников без проверки)

Всё это напрямую связано с тем, как написан HTML-код и как в нём обрабатываются данные пользователя. `Цель урока` — показать, как даже простая форма может стать уязвимой, если забыть о проверке и правильной обработке данных. 

## Что такое HTML

`HTML` (HyperText Markup Language) — язык разметки, который задаёт структуру веб-страницы. HTML не является языком программирования — он описывает что должно быть отображено: текст, формы, изображения, кнопки, ссылки.

Каждый элемент HTML представляет собой тег — `парную` конструкцию вида:
```html
<p>Это абзац текста</p>
```
Есть также `непарные` теги, например:
```html
<img src="image.png" alt="Картинка">
```
HTML работает по принципу иерархии: документ состоит из «дерева» элементов, вложенных друг в друга.

Минимальная структура страницы:
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Пример страницы</title>
</head>
<body>
  <h1>Заголовок страницы</h1>
  <p>Текст и контент</p>
</body>
</html>
```
Важно понимать: Всё, что пользователь видит, приходит в браузер именно в виде HTML. Ошибки в HTML и неосторожная работа с данными могут привести к серьёзным последствиям. Например, если пользовательский ввод вставляется в HTML без фильтрации — появляется `XSS`.

## Что такое CSS
`CSS` (Cascading Style Sheets) — язык оформления, который управляет внешним видом элементов HTML. Он позволяет задавать цвета, шрифты, отступы, размеры и оформление.

Пример простого CSS:
```css
body {
  background-color: #f9f9f9;
  font-family: Arial, sans-serif;
}

button {
  background-color: #4CAF50;
  color: white;
  border: none;
  padding: 10px;
  border-radius: 5px;
}
```
CSS не влияет на логику, но ошибки в нём тоже могут привести к проблемам: например, если неправильно задана прозрачность или размещение, это может создать условия для `clickjacking` (перехвата кликов через iframe).

## HTML через призму безопасности
В контексте AppSec важно понимать как ошибки в разметке и валидации приводят к уязвимостям. Типичные ошибки новичков:
* Использование `innerHTML` (способ в JavaScript прочитать или изменить HTML‑код внутри какого‑то элемента на странице) без фильтрации в `JavaScript` (позже в курсе станет одной из тем в модуле про `XSS`).
* Отсутствие атрибута `required` (атрибут HTML, который делает поле формы обязательным для заполнения) и валидации (клиентская, серверна более надежна) на форме — в систему могут попасть пустые данные.
* Хранение чувствительных данных прямо в HTML (например, email, токен).
* Неправильное использование тегов `<form>` и `<input>` без указания метода (GET/POST).

Помните: HTML — не просто дизайн. Это «передний вход» в приложение, и злоумышленники часто атакуют именно через формы и скрипты.

## Основные HTML-теги 
Перед тем как приступить к практике, давайте посмотрим на самые распространённые HTML-теги, с которыми мы будем работать в этом модуле

|Тег|Пояснение|
|---|---|
|`<!DOCTYPE html>`|Сообщает браузеру, что документ написан на языке HTML5.|
|`<html>`|Корневой элемент страницы. Всё содержимое сайта находится внутри этого тега.|
|`<head>`|Содержит служебную информацию о странице: заголовок, стили, метаданные.|
|`<meta>`|Метаданные страницы. Например, `<meta charset="UTF-8">` задаёт кодировку.|
|`<title>`|Заголовок страницы во вкладке браузера.|
|`<link>`|Подключает внешние файлы (например, таблицы стилей CSS).|
|`<script>`|Подключает или вставляет JavaScript-код.|
|`<body>`|Основная видимая часть страницы.|
|`<h1>–<h6>`|Заголовки разных уровней: от самого крупного (`<h1>`) до самого мелкого (`<h6>`).|
|`<p>`|Абзац текста.|
|`<a>`|Создаёт ссылку. Пример: `<a href="https://example.com">Ссылка</a>`.|
|`<img>`|Добавляет изображение. Пример: `<img src="photo.jpg" alt="Описание">`.|
|`<ul>, <ol>, <li>`|Создают списки: маркированный, нумерованный и элементы списка.|
|`<div>`|Контейнер для группировки элементов. Часто используется с CSS.|
|`<span>`|Встроенный контейнер для выделения части текста.|
|`<form>`|Создаёт форму для ввода данных пользователем.|
|`<input>`|Поле ввода. Может быть text, password, email, checkbox и др.|
|`<label>`|Подпись к полю ввода. Делает форму удобнее для пользователя.|
|`<button>`|Кнопка. Может отправлять форму или запускать действие.|
|`<select>, <option>`|Выпадающий список и его варианты выбора.|
|`<textarea>`|Поле для ввода многострочного текста.|
|`<table>, <tr>, <th>, <td>`|Создают таблицу: строки и ячейки данных.|
|`<header>, <nav>, <main>, <footer>`|Современные семантические теги: структура страницы.|
|`<section>, <article>`|Используются для разделения контента на логические блоки.|
|`<iframe>`|Встраивает другую страницу внутрь текущей. Используется с осторожностью.|
|`<style>`|Позволяет вставлять CSS прямо в HTML.|
|`<strong>, <em>`|Выделяют важный текст: жирный или курсив.|
|`<hr>`|Горизонтальная линия-разделитель.|
|`<input type="submit">`|Кнопка для отправки формы.|
|`<input type="checkbox">`|Флажок для выбора опции.|
|`<input type="radio">`|Радио-кнопка — выбор одного варианта из группы.|
|`<input type="file">`|Поле для загрузки файла.|
|`<input type="date">`|Поле выбора даты.|
|`<input type="number">`|Поле для числового ввода.|
|`<meta name="viewport">`|Помогает адаптировать страницу под мобильные устройства.|

`HTML` — это основа любого веб-приложения. Чем лучше вы понимаете его структуру, тем легче вам будет разбираться в безопасности и понимать, где именно могут появляться уязвимости, связанные с пользовательским вводом или некорректной вёрсткой. 

## Примеры страниц формы регистрации и переписки
***Страница 1 — Регистрация***. Безопасная версия

Создайте файл `register.html`.

Пример структуры:
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Регистрация</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h2>Регистрация пользователя</h2>
  <form action="/register" method="post">
    <label for="username">Имя пользователя:</label><br>
    <input type="text" id="username" name="username" required><br>

    <label for="email">Email:</label><br>
    <input type="email" id="email" name="email" required><br>
 
    <label for="password">Пароль:</label><br>
    <input type="password" id="password" name="password" required minlength="6"><br>
 
    <button type="submit">Зарегистрироваться</button>
  </form>
</body>
</html>
```
### Что важно отметить с точки зрения безопасности:
* Поля имеют атрибут `required` — данные не отправятся пустыми.
* Поле пароля имеет минимальную длину.
* Метод формы — `POST`, а не `GET` (чтобы данные не попадали в URL).
* Не храните никакие подсказки или ключи в HTML.

### Распространённая ошибка:

<!-- Никогда так не делайте -->
```html
<input type="hidden" name="is_admin" value="true">
```
Злоумышленник может легко изменить это значение через инструменты разработчика. Скрытое поле формы, которое передаёт на сервер информацию «этот пользователь — администратор».

***Страница 2 — Переписка***

Создайте файл `chat.html`.
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Переписка</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>
  <h2>Чат</h2>
  <div id="chat-box">
    <p><strong>Admin:</strong> Добро пожаловать в чат!</p>
  </div>

  <form id="message-form" action="/send" method="post">
    <input type="text" id="message" name="message" placeholder="Введите сообщение" required>
    <button type="submit">Отправить</button>
  </form>
</body>
</html>
```
Эта страница понадобится в будущем для демонстрации `XSS`. Пока мы просто создаём интерфейс.

### Безопасные практики, которые нужно запомнить:
* Любой ввод пользователя должен проверяться на стороне сервера (HTML-валидации недостаточно).
* Никогда не выводите введённые данные «как есть» в браузере без экранирования.
* Валидация в HTML нужна для удобства, но не защищает от атак.

### Простая стилизация

Создайте файл `style.css` и подключите его к обеим страницам.
Пример:
```css
body {
  background-color: #f4f4f4;
  font-family: Arial, sans-serif;
  margin: 40px;
}

form {
  background: white;
  padding: 20px;
  border-radius: 8px;
  box-shadow: 0 0 5px rgba(0,0,0,0.1);
  width: 300px;
}

input, button {
  width: 100%;
  padding: 8px;
  margin-top: 8px;
}

button {
  background-color: #007BFF;
  color: white;
  border: none;
  cursor: pointer;
}

button:hover {
  background-color: #0056b3;
}
```
Так вы создадите аккуратные, читаемые страницы.

### Валидация данных на клиенте
`HTML5` позволяет проверять корректность данных ещё до отправки формы.
Например:
* Поле `email` проверяется автоматически, если указать `type="email"`.
* Можно задать ограничение длины (`minlength`, `maxlength`).
* Можно указать шаблон (`pattern`), например:
```html
<input type="text" pattern="[A-Za-z0-9]{3,10}" title="Только латинские буквы и цифры, от 3 до 10 символов">
```
Это не защита, а удобство для пользователя. Все проверки всё равно нужно дублировать на сервере — злоумышленник может обойти HTML-валидацию с помощью инструментов разработчика или скриптов.

## Почему клиентская часть важна для AppSec
`HTML` и `CSS` определяют, какие данные вводит пользователь и как они передаются серверу.

Ошибки в форме — источник многих уязвимостей (`XSS`, `CSRF`, `утечки данных`). Понимая структуру HTML, вы сможете анализировать, где и как данные проходят через приложение.

После завершения урока вы:
* Познакомились с `HTML` и `CSS` и поняли, как они формируют клиентскую часть приложения.
* Создали две реальные страницы: `регистрации` и `переписки`, которые будут использоваться в следующих модулях.
* Освоили основы безопасной вёрстки: атрибуты `required`, типы полей, методы форм, базовую валидацию.
* Поняли, что клиентская валидация — это не защита, а лишь удобство, и что вся критическая проверка должна выполняться на сервере.

## Безопасная и уязвимая форма регистрации
В этом разделе мы разберём пример страницы регистрации. 

Сначала посмотрим на уязвимую версию, которая содержит типичные ошибки начинающих разработчиков. Затем рассмотрим исправленный вариант и подробно объясним, почему именно эти изменения делают приложение безопаснее.

Наша цель – не просто увидеть ошибки, а понять, как маленькая деталь в HTML может привести к серьёзным последствиям.

### Уязвимая версия страницы регистрации
Этот код выглядит как обычная форма, но в нём есть несколько ошибок, которые делают регистрацию небезопасной.
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Регистрация — Уязвимый пример</title>
  <link rel="stylesheet" href="/static/style.css">
  <script>
    function showWelcome(name) {
      // Пример опасного кода — вставляем текст в HTML как есть
      document.getElementById('welcome').innerHTML = "Привет, " + name + "!";
    }
  </script>
</head>
<body>
  <h1>Регистрация</h1>
  <!-- Ошибка: метод GET, пароль окажется в адресе -->
  <form id="regForm" action="/register" method="get">
    <label for="username">Имя пользователя</label><br>
    <input id="username" name="username"><br>

    <label for="email">Email</label><br>
    <input id="email" name="email"><br>

    <label for="password">Пароль</label><br>
    <input id="password" name="password"><br>

    <!-- Ошибка: скрытое поле с ролью -->
    <input type="hidden" name="is_admin" value="true">

    <!-- Ошибка: нет CSRF токена -->
    <button type="submit">Зарегистрироваться</button>
  </form>

  <div id="welcome"></div>

  <script>
    document.getElementById('regForm').addEventListener('submit', function(e) {
      var u = document.getElementById('username').value || '';
      if (u.length < 3) {
        alert('Имя слишком короткое');
        e.preventDefault();
      } else {
        // Небезопасный вывод
        showWelcome(u);
      }
    });
  </script>
</body>
</html>
```

### Разбор уязвимостей: что именно здесь неправильно и почему это важно
1. Метод формы: `GET`.
Когда форма использует `method="get"`, данные отправляются прямо в адресную строку.
Если вы введёте логин и пароль, они окажутся в URL – `/register?username=ivan&password=1234`.

Это выглядит безобидно, но на деле всё, что попадает в адрес, сохраняется:
* в истории браузера,
* в логах сервера,
* и даже может быть видно другим сайтам при переходе по ссылкам.

Таким образом, пароль пользователя может утечь буквально при первом клике. ***Вывод***: для регистрации, входа и любых операций с данными нужно использовать `method="post"`.

2. Скрытое поле с правами (`is_admin`).
В HTML любой пользователь может изменить значение поля, даже если оно скрыто.
Через инструменты разработчика можно поменять `<input type="hidden" name="is_admin" value="true">` на любое другое.

Если сервер «поверит» этим данным, злоумышленник сможет создать себе учётную запись администратора. ***Вывод***: никогда не храните важные вещи (права, баланс, статусы) в скрытых полях формы. Эти значения должен задавать только сервер.

3. Отсутствие `CSRF-защиты`. `CSRF` – это ситуация, когда чужой сайт может заставить браузер пользователя сделать действие на другом сайте, где он уже авторизован.
Если форма не защищена специальным токеном, браузер просто выполнит запрос, не понимая, что это подделка.

В нашем коде сервер не проверяет, откуда пришёл запрос – это значит, что чужой сайт может незаметно отправить такую же форму от имени пользователя. ***Вывод***: при каждой отправке формы сервер должен требовать уникальный токен, который подтверждает, что запрос пришёл с вашего сайта.

4. Использование `innerHTML`. Код `document.getElementById('welcome').innerHTML = "Привет, " + name;` вставляет введённый текст прямо в HTML. Если ввести что-то вроде `<b>Иван</b>`, браузер воспримет это как HTML и отрисует жирный текст. А если ввести вредный код – браузер может выполнить его.

Вывод: нельзя вставлять пользовательские данные в HTML напрямую. Используйте `textContent`, который вставляет только текст, а не HTML.

Теперь посмотрим, как те же элементы формы можно реализовать безопасно, не теряя функциональности.

## Безопасная версия страницы регистрации
```html
<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="utf-8">
  <title>Регистрация — Безопасный пример</title>
  <meta http-equiv="Content-Security-Policy" content="default-src 'self'; script-src 'self';">
  <link rel="stylesheet" href="{{ url_for('static', filename='style.css') }}">
</head>
<body>
  <h1>Регистрация</h1>

  <!-- Используем метод POST -->
  <form id="regForm" action="{{ url_for('register') }}" method="post" autocomplete="off" novalidate>
    <!-- Сервер добавит сюда CSRF токен -->
    <input type="hidden" name="csrf_token" value="{{ csrf_token }}">

    <label for="username">Имя пользователя</label><br>
    <input id="username" name="username" required maxlength="30" pattern="[A-Za-z0-9_.-]{3,30}" title="3–30 символов (латиница, цифры, _ . -)"><br>

    <label for="email">Email</label><br>
    <input id="email" name="email" type="email" required maxlength="254"><br>

    <label for="password">Пароль</label><br>
    <input id="password" name="password" type="password" required minlength="8" autocomplete="new-password"><br>

    <button type="submit">Зарегистрироваться</button>
  </form>

  <div id="welcome"></div>

  <script>
    document.getElementById('regForm').addEventListener('submit', function(e) {
      var username = document.getElementById('username').value || '';
      if (username.length < 3) {
        alert('Имя должно быть не меньше 3 символов');
        e.preventDefault();
        return;
      }
      // Безопасный вывод текста
      document.getElementById('welcome').textContent = "Привет, " + username + "!";
    });
  </script>
</body>
</html>
```
### Что изменилось и почему это важно

1. `method="post"`

Теперь данные передаются `в теле запроса`, а не в URL. Браузер не сохраняет пароли в истории, а серверные логи не содержат лишней информации.

Если дополнительно используется HTTPS, всё передаётся в зашифрованном виде. Это простое, но важнейшее правило любой формы с паролем.

2. Удалено скрытое поле `is_admin`

Никакие «привилегии» не должны определяться клиентом. Права пользователей, статусы и роли всегда устанавливаются и проверяются на сервере.
Клиент может вводить только то, что ему разрешено: логин, пароль, email. Всё остальное – за пределами его контроля.

3. Добавлен `CSRF-токен`

В форме появилось `скрытое поле с CSRF-токеном`. Этот токен генерирует сервер при отображении страницы и проверяет при отправке формы. Если токен подделан или отсутствует, сервер отклоняет запрос.

Это несложный механизм, но он защищает от ситуаций, когда другой сайт пытается «заставить» пользователя выполнить действие на вашем сайте.

4. Исправлен `способ вывода данных`

Теперь используется `textContent` вместо innerHTML. Браузер воспринимает переданный текст буквально, а не как HTML. Даже если пользователь введёт странные символы – они просто выведутся на экран, но не выполнятся как код. Это одна из самых частых ошибок у начинающих: использовать `innerHTML` там, где нужен обычный текст.

5. Мелкие, но полезные улучшения

Указаны `maxlength`, `required`, `pattern` – чтобы пользователь видел ошибки сразу при вводе.

Поле пароля сделано типом `password`, чтобы скрывать вводимые символы.

Добавлен небольшой Content-Security-Policy (`CSP`) – браузер теперь выполняет только свои скрипты, а не внешние.

### Вывод
Безопасность веб-приложений начинается с элементарных вещей. Эта форма регистрации выглядит почти так же, как первая, но внутри она совсем другая. Использование POST, удаление лишних полей, добавление CSRF и безопасный вывод текста – это фундамент.

Позже, когда мы будем работать с сервером (`Flask`), вы увидите, как эти простые принципы ложатся в основу защиты от самых частых атак – `XSS`, `CSRF` и уязвимостей прав доступа.
