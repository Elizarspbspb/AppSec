# Trivy (SCA)
`SCA` (Software Composition Analysis или анализа состава программного обеспечения).
## Что такое Trivy и зачем он нужен
`Trivy` — это комплексный сканер уязвимостей с открытым исходным кодом от `Aqua Security`. Его задача — просматривать то, из чего состоит ваше приложение и инфраструктура (контейнерные образы, файловые системы, репозитории, манифесты), сопоставлять это с базами известных уязвимостей и проблем конфигурации и выдавать осмысленный отчёт.

Для специалиста по безопасной разработке `Trivy` удобен тем, что он:
* ставится одной командой;
* одинаково запускается и на основной машине, и интегрируется в процесс сборки;
* покрывает и зависимости, и образы, и конфигурацию.

## Установка Linux (Debian / Ubuntu)
Компоненты:
```
sudo apt-get install wget apt-transport-https gnupg
```
Add repo: 
```
wget -qO - https://aquasecurity.github.io/trivy-repo/deb/public.key | gpg --dearmor | sudo tee /usr/share/keyrings/trivy.gpg > /dev/null

ИЛИ

wget -qO - https://get.trivy.dev/deb/public.key | gpg --dearmor | sudo tee /usr/share/keyrings/trivy.gpg > /dev/null

ИЛИ

wget --secure-protocol=TLSv1_2 -O - https://aquasecurity.github.io/trivy-repo/deb/public.key | gpg --dearmor | sudo tee /usr/share/keyrings/trivy.gpg > /dev/null
```
Set source: 
```
echo "deb [signed-by=/usr/share/keyrings/trivy.gpg] https://aquasecurity.github.io/trivy-repo/deb generic main" | sudo tee -a /etc/apt/sources.list.d/trivy.list
```
Install: 
```
sudo apt-get update && sudo apt-get install trivy
```

**Пример:**

Обычно знакомство начинают с самого простого — скана публичного образа:
```
trivy image alpine:3.15
```
Эта команда:
* скачивает образ alpine:3.15 (если его нет локально);
* анализирует установленные пакеты;
* показывает список уязвимостей с указанием CVE, версии пакета и уровня серьёзности.

По сути, это быстрая проверка базового образа, на котором строятся ваши контейнеры.

## Ключевые возможности Trivy
### Сканирование контейнерных образов
Основной сценарий: есть образ (Docker), и нужно понять, какие в нём уязвимые пакеты и библиотеки.

Обычный запуск:
```
trivy image my-registry.local/app-backend:1.2.3
```
`Trivy` пройдётся по слоям образа, определит дистрибутив (Alpine, Debian, Ubuntu и т.п.), найдёт пакеты и сопоставит их с базами CVE. Результат — таблица или JSON с уязвимостями, отсортированными по критичности.

### Сканирование файловой системы и проектов
Второй важный сценарий — скан собственного проекта: исходный код, lock-файлы, зависимости.

Например, чтобы просканировать текущий каталог:
```
trivy fs .
```
Здесь `Trivy`:
* ищет файлы зависимостей (например, package-lock.json, requirements.txt, go.mod);
* определяет менеджеры пакетов и версии библиотек;
* показывает уязвимости в зависимостях, даже если приложения ещё нет в контейнере.

Это удобно использовать и локально разработчиком, и в CI после сборки проекта.

### Сканирование Git-репозиториев
Если нужно проверить внешний/внутренний репозиторий целиком (в том числе на секреты), используют режим `repo`:
```
trivy repo https://github.com/org/repo
```
`Trivy` сам клонирует репозиторий во временную директорию, затем:
* анализирует зависимости;
* может искать секреты (пароли, токены, ключи) в коде и конфигурации.

Для внутренних аудитов такой режим позволяет быстро проверить чужой проект без подготовки отдельной среды.

### Kubernetes и конфигурации
`Trivy` умеет смотреть как на живой кластер, так и на `манифесты` и `Terraform`.

Примеры:

Сканирование всего кластера `Kubernetes`:
```
trivy k8s cluster
```
Здесь `Trivy`:
* подключается к кластеру по текущему `kubeconfig`;
* анализирует запущенные ресурсы (образы, конфиги);
* выявляет уязвимости в образах и типичные проблемы конфигурации.

### Сканирование конфигураций (IaC):
```
trivy config ./terraform
```
Эта команда анализирует `Terraform`-файлы (а также может работать и с Kubernetes-манифестами, Dockerfile и др.), проверяя их на известные анти-паттерны: отсутствующие ограничения, небезопасные параметры, открытые порты и т.д.

### Поиск секретов
`Trivy` умеет искать секреты в коде и файлах: токены, пароли, ключи. Это можно включать как часть скана файловой системы или репозитория.

Например:
```
trivy fs --security-checks vuln,secret .
```
Здесь `--security-checks` говорит: искать уязвимости в зависимостях (vuln) и возможные секреты (secret). В отчёте `Trivy` подсветит строки, которые похожи на ключи, токены и т.п. На практике такие результаты требуют ручной проверки, но позволяют быстро найти очевидные утечки.

### SBOM (Software Bill of Materials)
`Trivy` умеет генерировать `SBOM` — список компонентов и зависимостей образа или проекта в стандартизированных форматах (`CycloneDX`, `SPDX` и др.).

Пример генерации `SBOM` для образа в формате `CycloneDX`:
```
trivy image --format cyclonedx --output sbom-alpine.json alpine:3.15
```
Полученный файл можно:
* хранить как артефакт сборки;
* передавать другим инструментам анализа;
* использовать для отслеживания, какие библиотеки реально входят в ваши образы.

Это толко сбор зависимостей. Сам анализ:
```
trivy sbom sbom-alpine.json
```

## Чем Trivy отличается от других сканеров
Сканеров уязвимостей для образов и зависимостей довольно много (**Clair**, **Grype**, **Snyk** и др.), но у `Trivy` есть несколько практических особенностей.

**Во-первых, простота запуска.** `Trivy` — это единый бинарник, который:
* не требует поднятия отдельного сервера или базы;
* сразу после установки умеет сканировать образы и проекты.

**Во-вторых, скорость и кэширование.** `Trivy` кэширует результаты для пакетов и образов, поэтому повторные запуски по тем же целям идут быстрее. Это заметно при использовании в CI: первый запуск может занять больше времени, последующие проходят быстрее.

**В-третьих, источники данных.** `Trivy` опирается сразу на несколько баз:
* официальные CVE-базы дистрибутивов (Debian, Ubuntu, Red Hat, Alpine, Amazon Linux и др.);
* NVD (национальная база уязвимостей США);
* GitHub Security Advisories, GitLab advisories;
* собственные базы Aqua Security.

За счёт этого повышается полнота покрытия и уменьшается вероятность пропустить заметную уязвимость.

## Режимы работы Trivy
`Trivy` можно использовать по-разному в зависимости от сценария.

### 1. Одиночный режим (standalone)
Самый простой вариант — разовый запуск на локальной машине, как мы уже делали:
```
trivy image my-image:latest
trivy fs .
```
Такой режим подходит для локальной проверки разработчиком или однократного аудита.

### 2. Client/Server
Для крупных команд и CI-инфраструктуры есть режим `client/server`. 
Суть: поднимается Trivy-сервер, который хранит кэш уязвимостей и результатов, а клиенты обращаются к нему.
Схематично:

#### Запуск сервера (на отдельной машине/контейнере)
```
trivy server
```
#### На клиентах:
```
trivy image --server http://trivy-server.local:4954 my-image:latest
```
Это уменьшает дублирование скачивания баз и ускоряет сканы, когда много агентов CI гоняют `Trivy` по разным проектам.

## Встраивание в CI (на примере GitHub Actions)
В CI `Trivy` обычно запускают как отдельный шаг. На примере `GitHub Actions` это может выглядеть так (запоминать необязательно):
```
- name: Scan image with Trivy
  uses: aquasecurity/trivy-action@v0
  with:
    image-ref: my-registry.local/app-backend:1.2.3
    format: 'sarif'
    output: 'trivy-results.sarif'
```
Это позволяет:
* автоматически сканировать свежесобранный образ;
* сохранять результаты в формате SARIF;
* интегрировать их с `GitHub Advanced Security`.

Аналогично `Trivy` можно запускать в любом другом CI (GitLab CI, Jenkins, Azure DevOps) просто как команду в шаге пайплайна.

## Типы сканирования и примерные команды
Частично мы их уже затронули, соберём в одном месте для удобства, с минимальными пояснениями:

### Сканирование образа:
```
trivy image alpine:3.15
```
### Сканирование файловой системы/проекта:
```
trivy fs ./my-project
```
### Сканирование репозитория:
```
trivy repo https://github.com/org/repo
```
### Сканирование кластера Kubernetes:
```
trivy k8s cluster
```
### Сканирование конфигураций (IaC):
```
trivy config ./terraform
```
### Генерация SBOM для образа:
На самом деле Trivy сначала генерирует SBOM файлы зависимостей, а потом проверяет их. 
* cyclonedx - какой SBOM файл нужен, именно про уязвимости;
* sbom.json - файл с компонентами и его уязвимости
* alpine:3.15 - сам образ.
```
trivy image --format cyclonedx --output sbom.json alpine:3.15
```
Это толко сбор зависимостей. Сам анализ:
```
trivy sbom sbom.json
```

На практике вы будете комбинировать эти команды с нужными опциями: фильтрация по уровню серьёзности (`--severity`), выбор вида проверок (`--security-checks`), выбор формата (`--format/-f`) и т.д.

## Форматы вывода отчётов Trivy
`Trivy` позволяет выбирать формат отчёта в зависимости от того, кто его будет читать и как использовать.

Человеко-читаемый формат по умолчанию — таблица в терминале, без дополнительных флагов.

Для автоматизации часто используют JSON:
```
trivy image my-image:latest --format json --output trivy-report.json
```
`JSON` удобно разбирать скриптами, загружать в системы анализа или строить на его основе отчёты.

`HTML`-отчёты применяют, когда нужен «красивый» отчёт для ручного просмотра:
```
trivy image my-image:latest --format template --template "@contrib/html.tpl" --output trivy-report.html
```
(шаблон может быть встроенным или собственным.)

В итоге `Trivy` —  универсальный инструмент, который позволяет:
* одинаково удобно проверять образы, проекты, репозитории, кластеры и конфигурации;
* встроить проверки в локальную разработку, CI и эксплуатацию;
* опираться на богатую базу источников уязвимостей и форматов вывода.
