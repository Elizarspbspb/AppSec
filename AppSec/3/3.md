Этот урок посвящён основам HTML и CSS — языкам, на которых строится всё, что вы видите в браузере. Даже если вы не планируете становиться фронтенд-разработчиком, понимание структуры и поведения клиентской стороны — обязательная часть знаний специалиста по безопасности приложений (AppSec).

Почему? Потому что многие уязвимости рождаются именно на стороне клиента.





XSS (Cross-Site Scripting - внедрение вредоносного JavaScript-кода в страницу, выполняющегося у пользователя)



Clickjacking (обман, при котором пользователь кликает по скрытым элементам на странице, встроенной в чужой сайт)



Уязвимости в формах ввода (ошибки, позволяющие злоумышленнику отправить или подменить данные например, через непроверенные поля форм)



Небезопасные JavaScript-скрипты (скрипты, которые можно изменить, подменить или использовать для кражи данных например, из внешних источников без проверки)

Всё это напрямую связано с тем, как написан HTML-код и как в нём обрабатываются данные пользователя.

Цель урока — показать, как даже простая форма может стать уязвимой, если забыть о проверке и правильной обработке данных. В этом модуле вы создадите две реальные страницы, которые позже превратятся в учебный полигон для практических атак и защиты.





Что такое HTML

HTML (HyperText Markup Language) — язык разметки, который задаёт структуру веб-страницы. HTML не является языком программирования — он описывает что должно быть отображено: текст, формы, изображения, кнопки, ссылки.

Каждый элемент HTML представляет собой тег — парную конструкцию вида:

<p>Это абзац текста</p>

Есть также непарные теги, например:

<img src="image.png" alt="Картинка">

HTML работает по принципу иерархии: документ состоит из «дерева» элементов, вложенных друг в друга.

Минимальная структура страницы:

<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Пример страницы</title>
</head>
<body>
  <h1>Заголовок страницы</h1>
  <p>Текст и контент</p>
</body>
</html>

Важно понимать:





Всё, что пользователь видит, приходит в браузер именно в виде HTML.



Ошибки в HTML и неосторожная работа с данными могут привести к серьёзным последствиям. Например, если пользовательский ввод вставляется в HTML без фильтрации — появляется XSS.





Что такое CSS

CSS (Cascading Style Sheets) — язык оформления, который управляет внешним видом элементов HTML.
Он позволяет задавать цвета, шрифты, отступы, размеры и оформление.

Пример простого CSS:

body {
  background-color: #f9f9f9;
  font-family: Arial, sans-serif;
}
 

button {
  background-color: #4CAF50;
  color: white;
  border: none;
  padding: 10px;
  border-radius: 5px;
}

CSS не влияет на логику, но ошибки в нём тоже могут привести к проблемам: например, если неправильно задана прозрачность или размещение, это может создать условия для clickjacking (перехвата кликов через iframe).





HTML через призму безопасности

В контексте AppSec важно понимать как ошибки в разметке и валидации приводят к уязвимостям. Типичные ошибки новичков:





Использование innerHTML без фильтрации в JavaScript (позже в курсе станет одной из тем в модуле про XSS).



Отсутствие атрибута required и валидации на форме — в систему могут попасть пустые данные.



Хранение чувствительных данных прямо в HTML (например, email, токен).



Неправильное использование тегов <form> и <input> без указания метода (GET/POST).

Помните: HTML — не просто дизайн. Это «передний вход» в приложение, и злоумышленники часто атакуют именно через формы и скрипты.







Основные HTML-теги 

Перед тем как приступить к практике, давайте посмотрим на самые распространённые HTML-теги, с которыми мы будем работать в этом модуле







Тег



Пояснение





<!DOCTYPE html>



Сообщает браузеру, что документ написан на языке HTML5.





<html>



Корневой элемент страницы. Всё содержимое сайта находится внутри этого тега.





<head>



Содержит служебную информацию о странице: заголовок, стили, метаданные.





<meta>



Метаданные страницы. Например, <meta charset="UTF-8"> задаёт кодировку.





<title>



Заголовок страницы во вкладке браузера.





<link>



Подключает внешние файлы (например, таблицы стилей CSS).





<script>



Подключает или вставляет JavaScript-код.





<body>



Основная видимая часть страницы.





<h1>–<h6>



Заголовки разных уровней: от самого крупного (<h1>) до самого мелкого (<h6>).





<p>



Абзац текста.





<a>



Создаёт ссылку. Пример: <a href="https://example.com">Ссылка</a>.





<img>



Добавляет изображение. Пример: <img src="photo.jpg" alt="Описание">.





<ul>, <ol>, <li>



Создают списки: маркированный, нумерованный и элементы списка.





<div>



Контейнер для группировки элементов. Часто используется с CSS.





<span>



Встроенный контейнер для выделения части текста.





<form>



Создаёт форму для ввода данных пользователем.





<input>



Поле ввода. Может быть text, password, email, checkbox и др.





<label>



Подпись к полю ввода. Делает форму удобнее для пользователя.





<button>



Кнопка. Может отправлять форму или запускать действие.





<select>, <option>



Выпадающий список и его варианты выбора.





<textarea>



Поле для ввода многострочного текста.





<table>, <tr>, <th>, <td>



Создают таблицу: строки и ячейки данных.





<header>, <nav>, <main>, <footer>



Современные семантические теги: структура страницы.





<section>, <article>



Используются для разделения контента на логические блоки.





<iframe>



Встраивает другую страницу внутрь текущей. Используется с осторожностью.





<style>



Позволяет вставлять CSS прямо в HTML.





<strong>, <em>



Выделяют важный текст: жирный или курсив.





<hr>



Горизонтальная линия-разделитель.





<input type="submit">



Кнопка для отправки формы.





<input type="checkbox">



Флажок для выбора опции.





<input type="radio">



Радио-кнопка — выбор одного варианта из группы.





<input type="file">



Поле для загрузки файла.





<input type="date">



Поле выбора даты.





<input type="number">



Поле для числового ввода.





<meta name="viewport">



Помогает адаптировать страницу под мобильные устройства.


HTML — это основа любого веб-приложения. Чем лучше вы понимаете его структуру, тем легче вам будет разбираться в безопасности и понимать, где именно могут появляться уязвимости, связанные с пользовательским вводом или некорректной вёрсткой. 
В следующих уроках мы будем использовать эти теги для создания страниц, на которых будем демонстрировать реальные примеры атак и способов защиты.
 





Приведем примеры страниц формы регистрации и переписки

Страница 1 — Регистрация. Безопасная версия

Создайте файл register.html.                                                                                                                      
Пример структуры:

<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Регистрация</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>

  <h2>Регистрация пользователя</h2>
  <form action="/register" method="post">
    <label for="username">Имя пользователя:</label><br>
    <input type="text" id="username" name="username" required><br>
 

    <label for="email">Email:</label><br>
    <input type="email" id="email" name="email" required><br>
 

    <label for="password">Пароль:</label><br>
    <input type="password" id="password" name="password" required minlength="6"><br>
 

    <button type="submit">Зарегистрироваться</button>
  </form>
</body>
</html>

Что важно отметить с точки зрения безопасности:





Поля имеют атрибут required — данные не отправятся пустыми.



Поле пароля имеет минимальную длину.



Метод формы — POST, а не GET (чтобы данные не попадали в URL).



Не храните никакие подсказки или ключи в HTML.

Распространённая ошибка:

<!-- Никогда так не делайте -->

<input type="hidden" name="is_admin" value="true">

Злоумышленник может легко изменить это значение через инструменты разработчика.



Страница 2 — Переписка

Создайте файл chat.html.

<!DOCTYPE html>
<html lang="ru">
<head>
  <meta charset="UTF-8">
  <title>Переписка</title>
  <link rel="stylesheet" href="style.css">
</head>
<body>

  <h2>Чат</h2>
  <div id="chat-box">
    <p><strong>Admin:</strong> Добро пожаловать в чат!</p>
  </div>

  <form id="message-form" action="/send" method="post">
    <input type="text" id="message" name="message" placeholder="Введите сообщение" required>
    <button type="submit">Отправить</button>
  </form>
</body>
</html>

Эта страница понадобится в будущем для демонстрации XSS. Пока мы просто создаём интерфейс.

Безопасные практики, которые нужно запомнить:





Любой ввод пользователя должен проверяться на стороне сервера (HTML-валидации недостаточно).



Никогда не выводите введённые данные «как есть» в браузере без экранирования.



Валидация в HTML нужна для удобства, но не защищает от атак.



Простая стилизация

Создайте файл style.css и подключите его к обеим страницам.
Пример:

body {
  background-color: #f4f4f4;
  font-family: Arial, sans-serif;
  margin: 40px;
}

form {
  background: white;
  padding: 20px;
  border-radius: 8px;
  box-shadow: 0 0 5px rgba(0,0,0,0.1);
  width: 300px;
}

input, button {
  width: 100%;
  padding: 8px;
  margin-top: 8px;
}

button {
  background-color: #007BFF;
  color: white;
  border: none;
  cursor: pointer;
}

button:hover {
  background-color: #0056b3;
}

Так вы создадите аккуратные, читаемые страницы.





Валидация данных на клиенте

HTML5 позволяет проверять корректность данных ещё до отправки формы.
Например:





Поле email проверяется автоматически, если указать type="email".



Можно задать ограничение длины (minlength, maxlength).



Можно указать шаблон (pattern), например:

<input type="text" pattern="[A-Za-z0-9]{3,10}" title="Только латинские буквы и цифры, от 3 до 10 символов">

Это не защита, а удобство для пользователя. Все проверки всё равно нужно дублировать на сервере — злоумышленник может обойти HTML-валидацию с помощью инструментов разработчика или скриптов.





Почему клиентская часть важна для AppSec





HTML и CSS определяют, какие данные вводит пользователь и как они передаются серверу.



Ошибки в форме — источник многих уязвимостей (XSS, CSRF, утечки данных).



Понимая структуру HTML, вы сможете анализировать, где и как данные проходят через приложение.

В будущем мы будем намеренно модифицировать эти страницы, чтобы показать, как из обычной формы можно создать уязвимое приложение.
