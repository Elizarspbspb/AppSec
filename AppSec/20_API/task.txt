API Mass Assignment – апгрейд до администратора через PATCH /api/me

 

Адрес доступа к лаборатории: 

http://62.173.140.174:36113



Условие задачи

На выданном стенде реализовано учебное API работы с профилем:





Страница /profile показывает ваши текущие данные:





id, username, display_name, email, role, is_admin.



Эндпоинт GET /api/me возвращает те же данные в формате JSON.



Страница /api/patch-sim имитирует работу инструмента типа Burp:





на ней есть большое текстовое поле для JSON-тела запроса,



кнопка «Отправить PATCH-запрос», которая отправляет введённый JSON на сервер.

Цель:





Используя уязвимость в обработке JSON на стороне сервера, изменить свои права так, чтобы ваш пользователь стал администратором.



После успешной атаки:





на странице /profile и в симуляторе /api/patch-sim появляется бейдж
«Лабораторная работа решена успешно»,



дополнительно на экране отображается флаг.

Нужно подготовить один файл-отчёт (PDF или DOCX).

Подсказки







Обратите внимание, какие поля присутствуют в JSON-ответе GET /api/me, кроме тех, что явно показываются на странице профиля.



Подумайте, какие поля могут отвечать за права доступа (роль, признак администратора и т.п.), и что произойдёт, если такие поля включить в тело «PATCH-запроса».



Попробуйте сначала отправить небольшой JSON с изменением одного или двух полей и посмотрите, как это влияет на данные, которые возвращает API.
