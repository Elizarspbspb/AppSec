Возьмите однин из своих проектов и оформите его как Git-репозиторий с понятной историей изменений.

Цель:





освоить базовые команды Git,



научиться работать с ветками,



уметь просматривать историю (git log, git show).



Что нужно сделать





Создать репозиторий проекта





В папке с выбранным проектом инициализировать репозиторий.



Создать первый коммит с «базовой версией» проекта.



Добавить изменение в основной ветке





Внести небольшое изменение в проект (например, текст на странице, описание в README, мелкую правку в коде).



Закоммитить это изменение с понятным сообщением.



Поработать с веткой





Создать отдельную ветку.



В этой ветке внести ещё одно осмысленное изменение (ещё один небольшой функционал, текст, баннер и т.п.).



Закоммитить изменение в ветке.



Вернуться в основную ветку и добавить в неё исправление (merge).



Посмотреть историю

Обязательно использовать и показать:
git log — история коммитов;
хотя бы один из вариантов:
git log --oneline,
git log --oneline --graph (если хотите красивый вид).





Изучить отдельный коммит

Использовать:
git show <hash> — показать содержимое одного выбранного коммита.

 

Что сдать

Краткое описание проекта
3–5 предложений: какой стенд вы выбрали и что он демонстрирует.



Краткий перечень использованных команд Git
Не пошаговая инструкция, а список с пояснениями, например:





git init — создал репозиторий для проекта;



Выводы git log и git show





Вставьте в отчёт:





фрагмент вывода git log или git log --oneline с вашей историей коммитов;



вывод git show для одного выбранного коммита (где видно diff).



Можно скриншотами, можно вставить текстом.



Скриншот структуры проекта





Скрин структуры папки (IDE/терминал), где видно:





файлы вашего стенда,



наличие папки .git.



Короткий вывод (3–5 предложений)

Ответьте на вопросы:





чем удобны ветки в Git;



зачем смотреть git log и git show;

 

Требования к зачёту





Репозиторий инициализирован, есть несколько коммитов.



Было создано минимум одна ветка, в ней сделан коммит, после чего ветка слита в основную.



В отчёте есть:





пример вывода git log / git log --oneline,



пример вывода git show <hash>.
